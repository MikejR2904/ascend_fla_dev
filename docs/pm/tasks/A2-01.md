# A2-01 定性 ascriptor 的 split-K FP32 cube 数值缺陷（a2 profile）

- 波次 / SoC：W0 / a2（**纯主机侧**：`ascriptor check` / sim / pipesim，不需要 NPU）
- 优先级：P0 · 时限：12h · 依赖：无
- 需要：ascriptor workspace（按其 `agent/compatibility.json` 选 library/kernels 修订，并在 DONE 里写明修订号）
- 写集：`benchmarks/a2/repro_splitk_fp32.py`、`benchmarks/a2/README.md`
- 证据目录：`tmp/A2-01/`（不提交）

## 为什么是 P0

用户 2026-09-14 决定首波在 A2 上做算子与整模型（见 `AGENTS.md` §2）。而 ascriptor 侧在 2026-09-06 把
A2/A3 标为 deferred（`docs/matrix/ops.json` 的 `ascriptor_pin.release_scope`，决策号 D-250），
**附带一个未解决的 split-K FP32 cube 数值缺陷**。在搞清楚它之前，A2 上任何算子结论都不可信 ——
所以 A2 所有算子任务都依赖本任务（真机复现在 A2-11）。

## 背景（摘录，任务自包含）

- 本仓在 A5 上跑通的 KDA kernel 链：
  - 前向 5 个：上游 ascriptor `kernels/projects/a5/kda_fwd`；其中 gate / intra / wy 三个由本仓
    `kernels/projects/a5/kda_fwd_stable` 替换（门控跨度的数值稳定改写）。
  - 反向 9 个：上游 `kda_bwd`；finalize_pre / finalize_post 由本仓 `kda_bwd_stable` 替换。
  - decode 1 个：本仓自写 `kernels/projects/a5/kda_fused_recurrent`。
- GDN：上游 `gdn_fwd` / `gdn_bwd`，五阶段 preprocess / inverse / recompute / scores / recurrent。
- **"split-K" 的确切含义先从 ascriptor 侧的记录里查实**，不要按字面猜（可能指 K 维被切给子核、
  cube 按 K 分块、或别的东西）。

## 步骤

1. 在 ascriptor workspace 里找到缺陷的原始记录（`agent/` 下的决策、handoff、issue；D-250 相关条目），
   摘录：现象、复现形状、已知或怀疑的根因、为什么 defer。
2. 查实 ascriptor 的 a2 profile：名字、cube / vec 核数、UB 容量、支持的 dtype。记录来源文件与行号。
   **注意** A5 上 profile 声明 32 cube / 64 vec 而物理只有 28 / 56，超出会在 barrier 上死锁 ——
   a2 是否有同类出入，本任务只能从文档查，真机确认在 A2-10。
3. 写最小复现 `benchmarks/a2/repro_splitk_fp32.py`：CPU 参考 vs sim；若缺陷与流水/同步有关，再加 pipesim。
   `--profile a2|a5` 参数化，**同一 kernel 在 a5 profile 下作对照组**。
4. sim / pipesim 复现不了时：给出论证（例如缺陷只在 CANN 编译或硬件执行时出现），
   并在同一脚本里备好 `--launcher aclnn` 的真机复现入口，留给 A2-11。
5. 逐个扫 KDA 15 个 + GDN 10 个 kernel，判定是否用到触发构造。**逐个列**（kernel、文件、行、命中/未命中、理由），
   不写"其余类似"。
6. 列候选绕行方案（改写避开该构造 / 换 dtype / 派生单元 / 按 §7 装闸报错），每个配 fp32 下的数值验证计划。

## 验收
