# PK-01 PKDA / PGDN：先把权威来源与语义定下来

- 波次 / SoC：W0 / any。纯主机侧调研，不需要真机也不需要 ascriptor
- 优先级：P2 · 时限：10h · 依赖：无
- 需要：fla（确认它到底有没有）
- 写集：`docs/research/pkda_semantics.md`

## 为什么这条不是"实现任务"

用户 2026-09-16 点名 PKDA 要细化排期。但排实现任务之前有个硬前提没满足：**本仓没有 oracle。**

- `fla 0.5.2` 的 `fla/ops/` 下**没有 pkda**（实测列过：abc、attn、comba、delta_rule、gated_delta_rule、
  gated_oja_rule、gdn2、gla、kda、mesa_net、titans… 没有 pkda 或 pgdn）。
- 那三份 Gemini 规划文档只给了机制描述：测试时回归（TTR）框架、自适应测试时核（ATK）、
  对角 Hessian 预条件 `p_t = λp_{t-1} + k_t⊙k_t`、`k̃_t = k_t/(p_t+ε)`。**没有可对照的参考实现。**

`AGENTS.md` §6 的双 oracle 纪律要求每个算子都对两个独立参考判定，其中 fla 的 `naive.py` 是语义权威。
没有权威来源就写不出验收判据，写不出判据的任务派下去只会产出"看起来对"的东西。所以本任务只做一件事：
**把权威来源找出来，或者证明它现在还不存在。**

## 步骤

1. 在 fla 上游（GitHub 主仓、未发布分支、PR、issue）搜 pkda / pgdn / preconditioned delta /
   test-time regression / adaptive test-time kernel。记下找到的每一处：仓库、分支、commit、文件路径。
   找不到就如实写找不到，并列出搜过哪些地方。
2. 找论文出处。Gemini 文档提到 TTR 与 ATK，但没给引用。确认原始论文、作者、公式编号，
   与文档里的公式逐条对照，标出不一致的地方。
3. 如果既没有实现也没有论文可对齐：给出结论"当前无法定义验收判据"，并说明要满足什么条件才能排实现任务。
4. 如果找到了权威来源：写出语义定义（状态更新公式、张量形状、dtype、初始化、量程），
   并按 `AGENTS.md` §6「量程」一节逐处判定 `exp` / 除法 / 规约类算式 —— 特别是 `k_t/(p_t+ε)` 这个除法，
   `p_t` 会不会下溢到 0、ε 取多少、fp32 够不够。
5. 与 KDA 的关系：PKDA 若确实是"KDA 加一层预条件"，说明能复用本仓哪些资产
   （`kda_fwd_stable` / `kda_bwd_stable` 的哪几个 kernel、contract 的哪些约束照搬、哪些要改）。
   这决定了它是派生单元还是新单元。
6. 给排期建议：拆成几条任务、各自依赖什么、验收判据是什么。这份建议交 PM 落到看板，
   由仓库所有者决定放不放行（`AGENTS.md` §1：改变范围要显式决策）。

## 已知陷阱

- **Gemini 文档不是权威。** `docs/pm/PROTOCOL.md` §6 列了它已被证伪的八条说法（二阶 Neumann 当精确逆、
  fp16 门控、fp16 state、静默回退、bf16 rtol 判对错等）。引用它里面的公式时要标明"来源未核实"。
- 没有 oracle 就不要编一个出来当判据。宁可结论是"现在做不了"，也不要产出一个自洽但无从验证的实现。
- 硬件数字（PFLOPS、对齐粒度）一律不作为验收阈值。
