# A2-44 KDA 层语义修正（D1/D3）+ fla 式原始输入 API（不动 kernel）

- 波次 / SoC：W0 / any。纯主机侧 + CPU 测试，不需要真机
- 优先级：P2 · 时限：16h · 依赖：A2-40（已完成，本任务是它拆出来的子任务）
- 需要：fla（对照语义与 API）。不需要 ascriptor、不需要 NPU
- 写集：`ascend_fla/ops/kda/chunk.py`、`ascend_fla/ops/kda/fused_recurrent.py`、
  `ascend_fla/layers/kda.py`、`tests/test_kda_layer_semantics.py`（新文件）、
  `tests/test_kda_domain_checks.py`（新文件）

## 这条任务是怎么来的

`A2-40`（PR #85，`docs/research/a2_fusion_ops.md`）在整网融合算子的调研里发现了两处本仓层与 fla
的静默语义分叉（D1、D3），以及 `qk-l2norm-not-in-kernel` 的静默面比 `gaps.json` 原描述窄——真正
需要堵的口子是"调用方为了绕过 TypeError 而剥掉 fla 式 flags、传入未处理的原始值"。这三件事都
**不需要改 kernel**，可以在本仓 op/层这一侧独立修，因此拆成这条纯主机任务，不必等 A2-42 的
kernel 批次审批。

## 背景（从 A2-40 摘录，避免重新推导）

- **D1**：fla `x / sqrt(Σx² + 1e-6)`（`modules/l2norm.py`），本仓层里用
  `F.normalize(x, eps=1e-6)` = `x / max(‖x‖, 1e-6)`。‖x‖ 大时两者相对差远低于 bf16 分辨率；
  **‖x‖ 小时静默分叉**：‖x‖=1e-4 时 fla 输出范数 0.0995，本仓给 1.0。
- **D3**：fla 在 `use_short_conv=False` 分支对 q/k/v 各过一次 `F.silu`，本仓该分支不做，
  直接进 l2norm。Kimi-Linear 用短卷积碰不到，但构造参数接受这个开关，一旦被用到就是静默错误。
- **`qk-l2norm-not-in-kernel` 的真实静默面**：照抄 fla 的调用（传 `use_qk_l2norm_in_kernel=True`
  等 flags）在本仓会直接 `TypeError`，不是静默。真正静默的是调用方剥掉这些 kwargs 后传入原始
  （未归一化/未激活）的 q/k/g/beta——数值上完全合法，门控闸也未必拦得住。

`docs/matrix/gaps.json` 的 `kda-layer-l2norm-eps-formula-diverges`（P2）、
`kda-layer-missing-silu-when-no-short-conv`（P3）、`qk-l2norm-not-in-kernel`（P1，已补充说明）
三条记着这些结论，动手前先读一遍，不要重新推导。

## 步骤

1. **l2norm 公式对齐 fla（D1）**：把 `ascend_fla/layers/kda.py` 里的 `F.normalize(x, eps=1e-6)`
   换成 fla 的写法（分母整体加 eps 再开方，不是对范数取 max）。CPU 测试覆盖
   `‖x‖ ∈ {0, 1e-4, 1e-2, 1, 30}`，专门盯 ‖x‖=1e-4 这一行。
2. **`use_short_conv=False` 补 silu（D3）**：该分支对 q/k/v 补上 `F.silu`，对齐 fla。
   Kimi-Linear 现在不走这个分支，回归测试要显式构造 `use_short_conv=False` 的层来测，
   不能只测 Kimi 会用到的路径。
3. **给 `chunk_kda` / `fused_recurrent_kda` 加 fla 式原始输入 API**：签名加
   `A_log=None, dt_bias=None, use_qk_l2norm_in_kernel=False, use_gate_in_kernel=False,
   use_beta_sigmoid_in_kernel=False, check_domain=True`，参数名、默认值、`dt_bias` 形状
   （`[HV·K]`）与 fla v0.5.2 一致。**区别是本仓不静默忽略**：flag 为真但缺 `A_log` 就报错；
   `allow_neg_eigval`、`lower_bound`、`safe_gate` 仍然报错（沿用现有行为）。
   在 kernel 真正支持这几步之前（A2-42 之前），实现就是在 op 内部做和层里现在一样的 fp32
   计算，只是把三步从层挪进 op，l2norm 改用本任务第 1 步修好的公式。
4. **定义域检查（`check_domain=True`）**：只在 flag 为假、且传入的是"看起来像原始值"的那几路上
   检查：`g ≤ 0`、`beta ∈ (0,1)`、`‖q‖,‖k‖ ≤ 1+tol`（只在 chunk 路径做，decode 路径每次检查都是
   一次 launch，交给 A2-42 的融合解决，本任务不做 decode 路径的检查）。这是**启发式**检查
   （范数 < 1 的原始 q 抓不到），报错信息要点名"看起来传的是激活前的原始值，请传
   `use_*_in_kernel=True`"。`tol` 要按 bf16 舍入实测标定，写进测试注释，不能拍脑袋定数字。
5. **CPU 测试**（不需要真机、不需要 ascriptor）：
   - D1/D3 的回归测试，见步骤 1/2。
   - 新 API 的参数校验：flag 为真但缺 `A_log`/`dt_bias` 报错；`allow_neg_eigval` 等仍报错。
   - 定义域检查：分别单独传入原始 `g_raw`、`b_raw`、原始 q，各自必须报错且指名是哪一路；
     传入正常激活后的值不能误报。
   - 现有 `tests/test_kda_gating.py`、`test_kda_fwd_npu.py` 等不能因为签名变化而破坏
     （新增参数必须有默认值，`HV==H`/现有调用路径逐位不变）。

## 已知陷阱

- 不要顺手把 kernel 融合（A2-42 的范围）也做了——本任务明确"不动 kernel"，融合部分需要
  `kernel-batch-approval`，不是这条任务能决定的。
- `check_domain` 只覆盖 chunk 路径，decode 路径不要加检查（每次检查都是一次 launch，
  正是后续要压的开销，交给 A2-42）。
- 新增参数必须都有默认值且默认行为与现在完全一致——这是最容易漏测的回归点，
  不能只测新参数生效的那条路径，也要测"不传新参数"的旧路径逐位不变。
- `tol` 不能拍脑袋定，要实测 bf16 归一化向量的最大范数后再留余量，并把标定过程写进注释，
  否则下一个人还要重新摸一遍（`AGENTS.md` §6 的量程纪律同样适用于这种"容差"参数）。
