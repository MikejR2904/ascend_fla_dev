## 这条任务是怎么来的

用户 2026-09-19（D-PM-35）：BF16 计算必须在 kernel 里做，不能在 host 侧完成；后续 BF16 优先。GDA-03 的 FP32 反向不做 BF16 计算：按 D-PM-35，它的公共入口对 BF16 显式拒绝（不再 host 加宽），BF16 反向由本任务做成 kernel 侧。

## 范围

- 域与 GDA-03 逐项一致（分组 `HV%H==0`、`do` 与 `dht` 三种组合、`dq,dk:[B,T,H,128]` 组内求和、`dv:[B,T,HV,128]`、`dg,dbeta:[B,T,HV]`、无 `dh0`、无归一化项、`dq` 带 `scale`）。
  BF16：`q/k/v/do` 为 BF16，`dq/dk/dv` 由 kernel 直接写成 BF16；`dht`、`g`、`beta`、`dg`、`dbeta` 保持 FP32；检查点 / 重放 / 组内归约在 kernel 里，精度自选（写进文档）。
- 起点（只读）：GDA-03 的 FP32 derived 单元与上游 `a5.gdn_bwd`（BF16 operand，无 value-head 维度、零 initial state、不出 `dh0`）；上游的 BF16 精度模型**不是**本任务预算。
- 新建派生单元 `kernels/projects/a5/gdn_chunk_bwd_bf16/`；不改 `gdn_chunk_fwd*/**`、`gdn_chunk_bwd/**`（FP32）。

## 验收

- [ ] 通则 §1：BF16 公共入口的 host 算子审计（真机，附算子列表）；入口源码里不再有 BF16 路径的 `.float()` / `.to(dtype)`。
- [ ] 通则 §2：BF16 校准先行（误差地板 F 与预算写进 `docs/research/gdn_chunk_bwd_bf16.md`，实现前定死）。
- [ ] 通则 §3 真机：完整 workload 先跑；`HV/H ∈ {1,2,4,8}` × `C ∈ {1,2,3,64}`、多 batch、`do` / `dht` 三种组合；`bd` 间输出逐位相同；输入不被修改；NaN 预填。FP32 路径改前改后逐位相同。
- [ ] 通则 §5：同卡三轮三明治，BF16 新路径 vs 现有 FP32 路径，如实标注 baseline，不设速度门槛。
- [ ] 入口拒绝范围外的组合并说清哪条约束不满足；`git diff --stat` 对 `reserved_paths` 为空；没有改 FP32 单元源码。
- [ ] 预算：每个梯度对 A（pin 版 naive 的 CPU FP32 自动微分，喂 BF16 舍入后的输入）与 B（独立解析反向）各相对 L2 ≤ 2e-2（上游 `gdn_bwd` 自己的预算）且 ≤ 4F_g（F_g = 该梯度的 BF16 舍入地板，先校准）；
  两个 oracle 都先过 FP64 gradcheck（沿用 GDA-03 的口径），B 带负控制（零 / 取反 / ×1.25）。

## 已知陷阱

- 分组求和漏了会在 `HV>H` 时静默出错；`dq` 带 `scale`；对齐上游 reference 时先对齐 `scale`。
- `do` 是 C++ 关键字，内部 kernel 形参名要改（如 `dout`），公共 ABI 不变。
