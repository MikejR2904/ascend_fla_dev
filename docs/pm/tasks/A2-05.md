# A2-05 `state-layout-k-first`：fla/HF KDA cache 与本仓 cache 的适配器

- 波次 / SoC：W0 / any（纯 CPU）
- 优先级：P1 · 时限：8h · 依赖：无
- 需要：fla（作 oracle 与布局依据）
- 写集：`ascend_fla/compat/cache.py`、`ascend_fla/compat/__init__.py`、`tests/test_cache_adapter.py`

## 目标

接 Kimi-Linear 整模型（A2-08 / A2-16）时，HF/fla 那边的 cache 与本仓 `layers/kda.py` 的 cache 要互转。
**K=V=128 让转置错了也不报形状错** —— 这是 `gaps.json` 里 `state-layout-k-first` 标注的静默失败面。

## 背景（摘录）

- 本仓 `KimiDeltaAttention` 的 cache 是原地更新的字典（`docs/handoff.md` §8）：
  - `recurrent_state`：`[B, HV, 128, 128]` fp32，**K 在前**（`[B,HV,K,V]`）
  - `conv_state`：`(q, k, v)` 三个 `[B, D, conv_size]`
- fla 的 KDA layer 用 `state_v_first=True`（V 在前）。**以你装的 fla 源码为准**核实：`fla/layers/kda.py`、
  `fla/ops/kda/naive.py`、`fla/ops/kda/fused_recurrent.py`，以及 fla / HF 的 cache 容器类里 conv state 的布局与顺序。
- 本仓 oracle：`ascend_fla/reference/kda.py`；fla 的 `naive.py` 是语义权威（CPU fp32）。

## 要求

- `to_ours(fla_cache_or_layer_state) -> dict` 与 `to_fla(ours) -> …` 两个方向；对不上的布局/形状/dtype **报错**并写清实际值。
- 不做隐式 dtype 转换：state 必须 fp32，给了别的 dtype 报错。

## 验收

- [ ] **判别性测试**：用非对称的 state（`S != S.transpose(-1,-2)`），证明转错方向时结果会变 ——
      否则测试没有判别力。
- [ ] 从 fla 产生的 state 出发，经适配器接本仓的 torch 参考递推跑一步 decode，与 fla `naive` 递推逐元素比：
      fp32 下 max_abs_diff ≤ 1e-6（报实际值）。
- [ ] conv_state 同样验一步，并覆盖 `T < conv_size` 的补零情形。
- [ ] `to_fla(to_ours(x))` 逐位还原。
- [ ] 主机侧 `pytest tests/ -q` 计数只增不减。

## 验证命令

```bash
python -m pytest tests/test_cache_adapter.py -v
python -m pytest tests/ -q
```

## 已知陷阱

- **逐 token 报数，不报平均**：conv_state 漏传只会坏前 `conv_size−1` 个 token，平均会掩盖它。
- 不要引入对 fla 的**运行时**依赖：fla 只在测试里 import（`AGENTS.md` §1）。适配器按约定的布局写，测试用 fla 验证。
