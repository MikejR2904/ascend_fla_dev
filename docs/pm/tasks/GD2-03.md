# GD2-03 GDN-2 chunk 前向：性能优化（先 profile 再动手，一次一个改动）

- 波次 / SoC：W0（同 GD2-01/02，是 D-PM-16 那次例外的延续）/ a5
- 优先级：P2 · 时限：16h · 依赖：GD2-01（已 done）
- 需要：A5 真机（同一份已配置访问）、ascriptor workspace
- 写集：`kernels/projects/a5/gdn2_chunk_fwd/**`、`tests/test_gdn2_chunk_fwd.py`、
  `docs/research/gdn2_chunk_fwd_gate_range.md`

## 这条任务是怎么来的

GD2-01（PR #64，合入 `0397aa1`）交付的是一个**正确的 FP32 vector baseline**，不是性能优化过的版本。
issue #65 提议对它做性能优化：scan/output 两个 stage 里有重复算的 broadcast 标量指数和反复重载的
向量行，先 profile 再动手。这条排上看板，范围与 GD2-01 完全一致（同一个写集边界，D-PM-16
批的例外没有扩大），**不需要重新找所有者要一次新的范围决策**——它没有碰任何 reserved path，
没有改公开 API、没有改数学、没有改精度闸，纯粹是同一个已验收算法的实现层面优化。

**与 GD2-02 的关系**：两者写集不相交（GD2-02 只写 `benchmarks/bench_gdn2_chunk_fwd_a5.py`），
不互相阻塞。但如果两条任务同时有人在做，先完成的一方产出的证据可能被另一方的改动过时——
按 §3.4 的节奏互报 STATUS，PM 会盯着这条。

## 步骤

1. **先 profile 已验收的版本，不要先猜瓶颈**（AGENTS.md §6 铁律一：profile 之前不要相信任何
   性能推断）。真机上跑 T=4096 与 T=1024、H=16，同时拿 CPU golden 结果核对正确性没退步，
   记 stage 级与整体调用级计时。
2. **一次只改一处，逐次对照**（AGENTS.md §6 铁律二：一个算子名、一个进程、一份 build）。
   第一轮建议方向：把 scan/output 里重复算的标量指数和逐行重载向量化，累加顺序不变——
   **这轮不动 FP16/Cube 精度**，issue 里已经说清楚了，照办。
3. 每改一处，重跑：
   - 12 个契约 case 在 `block_dim ∈ {1, 8}` 上过，`bd=1` 与 `bd=8` 逐位相同——
     这是不需要参考的硬判据（AGENTS.md §6：核切分不改算式，不同就是切分 bug）。
   - 静态检查、缩小形状的 sim/pipesim 诊断、真机 source 检查，全部重新跑一遍，
     不是复用 GD2-01 时的旧记录——源码变了，证据要跟着重新产生。
4. **性能验收看两个长度是否都一致变快**：T=1024 与 T=4096 各自同卡同步三明治
   （baseline-candidate-baseline，warmup=10，repeat=50，三轮），跟 GD2-01 报告里已有的
   baseline 数字对照。**只留下两个长度都稳定变快的改动**；试过但没达标的改动，把对照数据
   留下来（负结果也是证据），不要悄悄删掉。

## 验收

- [ ] 已验收版本（`0397aa1`）在 T=4096/T=1024/H=16 上的 stage 级 + 调用级基线 profile 数字。
- [ ] 每个候选改动单独对照：改前改后的 profile 数字、正确性数字都在，不是只报最终版本。
- [ ] 12 个契约 case 在 bd=1 与 bd=8 上全过，两者输出逐位相同。
- [ ] 精度判据不放松：与 GD2-01 记录的 dual-oracle 预算（1e-4）一致，不因为要显性能而调松。
- [ ] 最终性能数字：T=1024 与 T=4096 都相对 GD2-01 记录的 baseline 一致变快，三轮同步三明治。
- [ ] 失败的候选改动留有对照记录，不隐藏负结果。
- [ ] `git diff --stat` 对 `docs/pm/board.json` 的 `reserved_paths` 为空；公开 API 签名不变。
- [ ] SoC + CANN 版本 + opp 算子包随每个真机数字一起报（PROTOCOL §3.7）。

## 已知陷阱

- 不要把这条做成"顺便修正确性"——数学已经在 GD2-01 验收过，这里只优化实现，
  改动前后的正确性判据必须逐位/按预算不变，变了就是引入了新 bug，不是优化。
- `AGENTS.md` §6 铁律三：缓存键不能比缓存贵。如果优化路径引入了任何形式的运行时缓存/查表，
  确认它的开销是 O(1) 级别。
- 复用 GD2-01 报告里的 baseline 数字做对照没问题，但**每一轮新的候选都要重新测**，
  不能拿旧版本的数字和新版本的数字混着比。
