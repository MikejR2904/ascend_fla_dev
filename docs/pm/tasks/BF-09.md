## 这条任务是怎么来的

BF-08 让训练路径的前处理（q/k 归一化、门控变换、beta sigmoid 及其梯度、`A_log` / `dt_bias` 的确定性两级归约）全部进了自编译 kernel，冻结的精度预算全过，但**补偿算术让完整前向 + 反向训练步慢了 11 倍**（BF-08 DONE 的原始 36 条样本，PM 从原始 JSON 复算）：

| 形状 | 旧 host 图（ms） | BF-08 candidate（ms） | 倍数 | Torch NPU 训练基线（ms） | 相对倍数 |
|---|---:|---:|---:|---:|---:|
| T1024 | 9.5750 | 106.7511 | 11.149 × | 39.9378 | 2.675 × |
| T4096 | 37.5994 | 425.7246 | 11.323 × | 140.5361 | 3.030 × |

逐 kernel（Level1 profiler，含扰动，不可与 clean 墙钟相加）：`kda_prep_backward_gate_bf16_f32_f32_kernel`（gate backward 第一阶段）**375.466 ms**（独立事件窗口 370.907 ms）占大头；`kda_prep_backward_norm_bf16_kernel` 两次共 19.566 ms；其余是既有 kernel。`ascend_fla/layers/kda.py` 的 KDA 层在 chunk 与 decode 上都用这三个 raw flag，所以 **KDA 层训练路径直接受影响**（默认无 flag 路径不受影响）。

## 目标与硬约束

- **目标（PM 建议的目标线，不是硬门槛，用户可改）**：在**不改变数值契约**的前提下，把 T4096 完整训练步降到旧 host 图的 1.25 倍以内（≈ 47 ms）。未达标不算失败，但必须给出瓶颈分析与下界。
- **硬约束（照 BF-08，一条都不放宽）**：冻结预算 `backward_budgets.json` **字节不变**（D-PM-54 / 55 / 56 的判读规则照用）；跨 `bd` 逐位相同；固定归约次序、无原子；155 / 105 门控与域不变；raw dtype 仍只接 BF16 / FP32；所有 vendor 在首次自定义 launch 前编完；训练路径无 host 算术 / 转换；D-PM-42 存量例外不在范围；每份最终资格回执的生产源码哈希必须与最终提交树逐个对上（出包前做机械检查）。
- **做不到目标怎么办**：**不要放宽预算**。守住上面的约束仍做不到，就如实报告瓶颈与下界；要放宽逐元素判据（例如「同一人口对旧 host 成对比较」或「按项幅值归一」）是**用户的决定**，PM 会带着你的数据去问。不引入任何近似回退、选择性补偿（需要可证明的灵敏度 / 误差界，本任务没有批准任何阈值）。

## 起点（BF-08 研究文档里的可优化项，供参考，不是指令）

gate 第一阶段对每个 32 BT 行 × 128 通道的工作项，每 64 lane 一半各自评估补偿 `exp`（多项式 + 8 次补偿平方）、`log1p` / softplus、sigmoid、多个乘积残差与固定五层部分归约，所有高 / 低分量都物化后再走固定归约；实测第二阶段全局归约很小、不是主因。方向：在证明同样误差界的前提下减少补偿超越函数与乘积的指令数、减少重复的 64 lane 临时 load / store、改善工作项流水与 tile 复用、减少冗余前处理 launch。**先量后动**：第一个提交里把 BF-08 合入后的三轮基线（旧 host 图、Torch NPU、当前 candidate）原样冻结，作为本任务的比较基准。

## 已知陷阱

- 「补偿版更准」不是理由：性能优化不能靠放宽误差；任何指令数的削减都要重新证明同样的误差界并在最终源码上重跑全网格。
- `A_log` / `dt_bias` 的两级归约必须仍然与 `bd` 无关且确定；优化流水 / tile 时别改变固定合并次序。
- 别把 Level1 profiler 的时长当 clean 墙钟（有扰动）；性能结论以三轮同步 clean 测量为准。
