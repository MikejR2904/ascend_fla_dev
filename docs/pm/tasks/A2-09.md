## 目标

在 `kernels/projects/a2/kda_bwd_stable/` 下按 ascriptor 的 unit 协议建出 KDA 反向单元（`unit.py` 导出 `make_inputs` / `reference` /
`execute`，加 `contract.json` 与 `run.py`），来源是上游 `a5/kda_bwd` 九个 kernel，其中 finalize_pre / finalize_post 取本仓
`a5/kda_bwd_stable` 的改写。

规矩与 A2-03 相同（先读 `docs/pm/tasks/A2-03.md` 的「更正与追加」）：

- a2 上向量侧是 UB 指令、没有 `@vf` / `@simt`，要重写；cube↔vector 交接走 GM workspace + mutex。
- 所有写同一块 L0C 的累加链显式 `barrier(Pipe.M)`、不分 dtype；BF16/FP16 的 `splitk` 不用 `M<64`，入口按 §7 报错。
- D-PM-35 / D-PM-37：BF16 的 kernel 直接吃 BF16、写 BF16，dtype / 格式转换都在 kernel 里，公共 ABI 按 token-major 直读直写。
- 新建的是**新单元**，不改上游与 A5 源码，不属于 kernel 批次。
- aclnn HostSpec 标量列表含 GM 形状里的全部符号维（`kda_bwd` 因此每个 kernel 多一个 `T`）；标量名以 `CompiledKernel.scalar_names` 为准。
- 反向的门控跨度有上溢风险（前向下溢、反向上溢，方向相反）：a2 契约里 `recommended_limit` / `accuracy_vs_span` 标 `untested`，不搬 A5 的 105。

## 验收

- [ ] 每个 kernel：`ascriptor check` 0 error，报 warning 数与 IR op 数，和 a5 版本对照。
- [ ] bwd 单元的 `run.py reference` 与 `run.py check --launcher sim` 在全部契约 case 上通过，另外再跑 (C∈{1,2}) × (HV∈{1,2,4}) × (bd∈{1,2})
      的边界网格，逐格报六项梯度（`dq/dk/dv/dg/dbeta/dh0`，以契约为准）的相对 L2；C 的奇偶档要覆盖（C=3 至少一格）。
- [ ] 契约的 board / aclnn stage 全部标 `untested`，证据字段不假装有真机数据。
- [ ] a5 单元一个字节都没改（`git diff --stat kernels/projects/a5` 为空）；也没改 A2-03 已合入的两个 a2 单元。
- [ ] **真机验证（D-PM-34）**：在你自己的 a2 真机上跑过并带证据——SoC、CANN 版本、内置算子包目录、原始日志行、逐项数字；结论只对实际跑过的那个 SoC 成立。
      A2-11 之前 A2 真机数字只作观测，不构成算子结论（`AGENTS.md` §2）。主机侧 / CPU 测试保留，但不能替代真机验证；DONE 里没有真机验证就 `REVIEW rework`。
