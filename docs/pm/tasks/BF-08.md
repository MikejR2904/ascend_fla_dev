## 目标

BF-07 之后，公开 `chunk_kda` 在**不需要梯度**（`no_grad` 或所有输入都不 `requires_grad`）时前处理已经在 kernel 里，但**需要梯度且 raw flag 开着**时仍走现有 host `_prepare_inputs` 的计算图（登记的存量例外）。本任务消除它：
训练路径的前处理也在自编译 kernel 里，**前向与反向的 host 侧都不再有前处理的算术 / 转换算子**，并且**一个梯度都不丢**。

## 梯度链

- 一个新的 `torch.autograd.Function`（或扩展 `_ChunkKDA`）包住前处理：前向调 BF-07 的 kernel，反向由**自编译 backward kernel** 产出 raw `q/k/g/beta` 与 `A_log` / `dt_bias` 的梯度，输入是 `chunk_kda_bwd` 给出的对「已处理的」q/k（BF16）、g（FP32）、beta（FP32）的梯度。公式（自行推导并在文档里逐项验证，下面只是提示）：
  - l2norm：`y = x·r`，`r = (Σx²+ε)^(−1/2)`，`ε = 1e-6`；`∂L/∂x = r·gy − r³·x·(x·gy)`（行内点积，K=128；梯度 dtype 与 raw 输入 dtype 一致）。
  - gate：`u = g + dt_bias`，`g_out = −exp(A_log)·softplus(u)`；`∂L/∂g = ∂L/∂g_out · (−exp(A_log)·sigmoid(u))`；`∂L/∂A_log[h] = Σ_{b,t,k} ∂L/∂g_out · g_out`；`∂L/∂dt_bias[h·128+k] = Σ_{b,t} ∂L/∂g_out · (−exp(A_log)·sigmoid(u))`。
  - beta：`∂L/∂beta = ∂L/∂beta_out · s·(1−s)`，`s = sigmoid(beta)`。
- **`A_log` / `dt_bias` 的梯度要对 (B, T) 归约**——跨核归约必须**确定性且与 `bd` 无关**：固定分块 + 固定合并次序的两级归约，工作区写在 GM 里，**不用原子加**；`bd` 间逐位相同仍是硬判据。
- 覆盖：raw `q/k/g/beta` 各自 / 全部 `requires_grad`、**「只有 `A_log` / `dt_bias` 要梯度」**、部分梯度组合、三个 flag 的 8 种开关（关闭的 flag 对应输入原样透传、梯度原样回传）。

## 预算与判据（实现前冻结，事后不得放宽）

沿用 BF-07 的做法：**先校准、第一个提交冻结**，PM 不预设数字，核对不比校准地板 3 倍更松、事后不放宽。必须定的量：三个 backward 输出（raw `q/k` 梯度、`g` / `dt_bias` / `A_log` 梯度、`beta` 梯度）对 FP64 参考与对旧 host 计算图（autograd 自动微分）的误差；端到端 `chunk_kda` 训练步的六个梯度对两个 CPU FP32 参考的预算沿用现有（dq / dv / dbeta / dh0 0.05、dk 0.15、dg 0.25，不放宽）。
FP32 输出的判据按 BF-07「2026-09-20 澄清」的口径（不设 ulp 通过线，改用对 FP64 地板的 3 倍；ULP 分布对两个比较对象都报并归类解释）。

## 2026-09-21 澄清（依申领人的 RISK `comparison-contract-boundary`（01:17Z）：反向 BF16 输出的「对两个对象各 ≤ 1 ULP」；PM 承认规格没覆盖这类输出）

PM 在 CPU（Torch 2.10.0+cpu）上把 RISK 里的脚本原样跑了一遍（种子 8008、B1 / T4096 / H32 / K128），**与 RISK 逐位一致**：7 个元素距 FP64 正确舍入 > 1 ULP、最大 3；三个 3 ULP 位置的 BF16 位（旧 host / 正确舍入）是 46025 / 46022、45872 / 45875、45988 / 45985；relL2 0.0016560061688898119、逐元素最大相对误差 0.019609933398464667。另有 4 个位置距离为 2（`[0,2526,31,62]`、`[0,2528,24,32]`、`[0,3253,4,51]`、`[0,3969,5,68]`），在这些位置上「对两个对象各 ≤ 1 ULP」只剩两者中点那一个 BF16 值可选。三个 3 ULP 位置上两个对象的 1 ULP 整数邻域不相交（如 [46024, 46026] 与 [46021, 46023]），**任何 BF16 candidate 都无法同时满足**——与 BF-07 澄清第 2 条同型：旧 host 自己对 FP64 就超 1 ULP（两项相消，条件数约 1.5e5–5.9e5），而语义权威是 FP64 / CPU FP32（D-PM-48），旧 host 是前任行为的观测。

**裁定（D-PM-54，PM；合入前单列给用户，用户可推翻）：**

1. **BF-07 澄清第 1 条（BF16 输出对 FP64 正确舍入与对旧 host 各 ≤ 1 ULP）对本任务的反向 BF16 输出不继承为通过线。** 对反向输出改用 BF-07 澄清第 2 条的口径：**不设 ULP 通过线**；相对 L2 ≤ min(1e-2, 3F)，逐元素相对误差预算 ≤ **3 × 旧 host 对 FP64 的实测地板**（同一度量下测、同一度量下判；norm 相关另受 1e-2 上限），随第一个提交冻结、事后不得放宽。这等价于「新 kernel 对 FP64 不得比旧 host 对 FP64 差过 3 倍」，不是「对旧 host 近似」。逐元素相对误差主要由相消位置决定、对多数元素很宽——所以相对 L2、ULP 分布与下面第 3 条的逐个列出才是主要的检测手段；你也可以**另加**按灵敏度归一的逐元素度量（误差 / 两项幅值之和）作为更紧的判据，不强制。
2. **权威**：算子级 = FP64 正确舍入；端到端 = 两个 CPU FP32 参考（预算不变）。旧 host 只是比较对象，对它的距离照报，不是通过线。
3. **ULP 报告**：对 FP64 正确舍入与对旧 host 两个对象都报完整分布；**每个距任一对象 > 1 ULP 的元素逐个列出**（位置、旧 host / candidate / FP64 正确舍入的 BF16 位、灵敏度行或条件数），逐类解释，PM 评审核实。RISK 里那 7 个位置属于此报告。**不把 3 ULP 写成阈值，不新增端点类。**
4. **归属由校准冻结**：哪些反向输出用第 1 条口径、哪些保留 BF-07 第 1 条的「对两个对象各 ≤ 1 ULP」，由第一个提交的校准数据定——旧 host 对 FP64 正确舍入出现过 > 1 ULP 元素的输出（分 dtype 组合逐个）用第 1 条口径，其余保留 ≤ 1 ULP 通过线；跨 (B,T) 归约的输出（`A_log` / `dt_bias`）同理，逐个写进冻结表并给出依据。
5. **检测力**：像 BF-07 一样，第一个提交里带「损坏输出对照」，由冻结预算逐个拒绝；对照要包含**接近预算边界**的一类（缺 `r³` 项、缺 `x·(x·gy)` 项、行内点积漏元素、归约漏块等），证明去掉 ULP 线之后预算仍能拒绝错误公式。
6. **不变**：端到端六个梯度对两个 CPU FP32 参考的预算（dq / dv / dbeta / dh0 0.05、dk 0.15、dg 0.25）、155 / 105 门控、域（raw 只接 BF16 / FP32）、D-PM-48 / 50 / 52 的端点框架；没有新端点类、没有新的通过线数字（数字仍由你的校准定、PM 核对不比地板 3 倍更松）。
7. 旧 host 的这个数值性质（BF16 norm 反向对 FP64 正确舍入最多 3 ULP，7 / 16,777,216 个元素，两项相消）请作为**发现**写进 `docs/research/kda_prep_backward.md`；不是回归、不是本任务要修的范围。

## 已知陷阱

- `A_log` / `dt_bias` 的梯度是**全局归约**，最容易做成与 `bd` 相关的顺序——一开始就按固定分块设计，并在归约里避开非确定性的累加顺序。
- l2norm 的行内点积与 BF-07 的行内求和用同一个固定 K=128 规约顺序，别在正反向里各写一套。
- 「只有参数要梯度」时 raw `g` 不要梯度但 `A_log` / `dt_bias` 要，反向仍要算 `∂L/∂g_out`；别因为 raw 输入不求导就跳过整条链。
- FMT-02 的性能教训（大 tile、别让每个 work-item 只做 64 个元素）同样适用。
