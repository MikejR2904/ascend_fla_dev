- 写集：`kernels/projects/a5/gdn2_chunk_fwd_bf16/**`、`ascend_fla/ops/gdn2_chunk_fwd.py`（只加 BF16 分派，FP32 路径逐位不变）、`tests/test_gdn2_chunk_fwd_bf16.py`、`docs/research/gdn2_chunk_fwd_bf16.md`

## 2026-09-19 追加（用户 D-PM-37）：格式转换也在 kernel 内，FP32 路径同样

FP32 路径里现存的 host 转换（`q.float()` 等）一并去掉，输出改前改后逐位相同；不得在 host 重排 / 复制 / 拷贝；两条路径都过 host 算子审计。不得触碰仓主轨道的保留路径。

## 2026-09-19 澄清（PM，依排队申领人在 #104 的只读预检）

原验收里的「多 batch」与现有入口矛盾：`ascend_fla/ops/gdn2_chunk_fwd.py` 与 GD2-01 单元的 `ref/reference.py` 都把公共域定成 **B=1、T=1..4096、H∈{1,16}、K=V=128**。PM 的裁定：

- **公共域与 GD2-01 完全相同（B=1、H∈{1,16}），BF16 路径不扩域、也不收窄域。** BF16 与 FP32 共用同一套入口校验，`B≥2` 显式报错并说清约束（这就是「拒绝范围外组合」一项对 batch 的覆盖）。
- 「多 batch」验收项删去；不要求 kernel 内部另证多 batch，也不为它扩公共 ABI。若你的 kernel 本来对 B 通用，可以在单元自带的契约里加几个 B≥2 的 case 作附带观测，但**不作为验收项、不写进公共入口的支持范围**。
- 扩域是另一件事（要单独立项，不夹带在 BF16 任务里）。其余验收项不变。

## 这条任务是怎么来的

用户 2026-09-19（D-PM-35）：BF16 计算必须在 kernel 里做，不能在 host 侧完成；后续 BF16 优先。GDN-2 chunk 前向（GD2-01）的 BF16 入口是 `q.float()` → FP32 kernel → 输出转回（`ascend_fla/ops/gdn2_chunk_fwd.py`），host 侧加宽；GD2-01 的真机数字也是 FP32 的。

## 范围

- 域与 GD2-01 的 FP32 前向逐项一致（erase gate、`w`、`initial_state` FP32 `[B,H,128,128]` 等，以现有入口的校验为准）；BF16 的 `q/k/v` → BF16 的 `o`，状态仍 FP32。
- 起点（只读）：GD2-01 的 FP32 单元（`kernels/projects/a5/gdn2_chunk_fwd`）。新建 `kernels/projects/a5/gdn2_chunk_fwd_bf16/`。
- **不得触碰仓主轨道的保留路径**（`board.json` 的 `reserved_paths`：`gdn2_fused_*`、`gdn2_short_conv_decode`、`gdn2_norm2_w12_swiglu` 等）；`ascend_fla/ops/gdn2/**` 同样保留。
- GDN-2 的门控跨度量程（GD2-01 观测最大 1520.9）要在 BF16 路径上重测（通则 §4）。
