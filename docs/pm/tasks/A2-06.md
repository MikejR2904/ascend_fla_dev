## 目标

矩阵现在只有一个隐含的 SoC，就是 A5。首波改到 A2/A3 上做之后，每一格状态都必须说明是在哪个 SoC 上得到的，
否则 A5 的 `passed` 会被读成 A2 也 passed，**矩阵就说谎了**（`AGENTS.md` §7/§8）。

顺带把另外两件一起做掉。`AGENTS.md` §8 要求"每一格的状态都应能指向一次真实的 check / profile 运行记录"，
可现在没有任何机器校验这一点；`docs/plan.md` 第三期的"矩阵 CI 生成"也一直没做。

## 背景（摘录）

`docs/matrix/{models,ops,gaps}.json` 是唯一权威，`docs/matrix/README.md` 由 `tools/gen_matrix.py` 生成，
`--check` 负责校验。状态词汇是 `passed` / `untested` / `gap` / `failed`，定义在 `ops.json` 的 `stage_vocabulary`。

`ops.json` 的 `linear_attention_ops[].validation` 现在是 `{stage: status}` 的平铺结构；`ascriptor_pin.release_scope`
标了 supported=a5、deferred=a2/a3；`models.json` 里有 `ascriptor_a5_abi`。

运行记录里不得出现机器信息（主机名、IP、账号、路径），机器一律用 `machine_specs.md` 里的代号。

## 要求

1. schema：`validation` 改成按 SoC 分层（例如 `{a5: {stage: status}, a2: {...}}`），现有内容原样迁到 a5 下，
   a2/a3 初始全是 `untested`。
2. 运行记录落在 `docs/matrix/runs/<日期>-<短名>.json`，字段有 `commit`、`soc`、`machine_alias`、`cann`、`command`、
   `numbers`、`log_ref`（`tmp/` 下的相对路径，仅供追溯）。
3. `tools/record_run.py`：从一次运行的参数生成记录文件，字段里含 IP 或绝对路径的一律拒绝。
4. `gen_matrix.py --check` 新增两项校验。一是每个 `passed` 格必须引用存在的运行记录，且记录的 `soc` 要和格子的 SoC 对得上。
   二是一次性豁免：迁移前已有的 A5 `passed` 格若找不到记录，放进显式的 `legacy_unrecorded` 列表 —— 要列出来，不是静默放行 ——
   并在生成的 README 里标注。
5. `.github/workflows/host-ci.yml` 跑主机侧的 `pytest tests/ -q`、`gen_matrix.py --check`、`pm_board.py --check`。
6. 迁移用一次性脚本做（可以放 `tools/` 后删，也可以留在 `tmp/` 并在 DONE 里给出），不要手改大块 json。
