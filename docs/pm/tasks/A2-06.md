# A2-06 支持矩阵按 SoC 分维 + 运行记录 + 主机侧 CI

- 波次 / SoC：W0 / any（纯主机侧）
- 优先级：P1 · 时限：12h · 依赖：PM-0
- 写集：`tools/gen_matrix.py`、`tools/record_run.py`、`.github/workflows/host-ci.yml`、`tests/test_gen_matrix.py`、
  `docs/matrix/**`（**本任务例外地持有矩阵 json 的写权**；进行期间 PM 暂缓应用其他任务的 matrix delta）

## 目标

1. 现在矩阵只有一个隐含的 SoC（A5）。首波改在 A2/A3 做之后，**每一格状态都必须说明是在哪个 SoC 上得到的**，
   否则 A5 的 `passed` 会被读成 A2 也 passed —— 矩阵说谎（`AGENTS.md` §7/§8）。
2. `AGENTS.md` §8 要求"每一格的状态都应能指向一次真实的 check / profile 运行记录"，目前没有机器校验这一点。
3. `docs/plan.md` 第三期的"矩阵 CI 生成"还没做。

## 背景（摘录）

- `docs/matrix/{models,ops,gaps}.json` 是唯一权威，`docs/matrix/README.md` 由 `tools/gen_matrix.py` 生成，`--check` 校验。
- 状态词汇：`passed` / `untested` / `gap` / `failed`（`ops.json` 的 `stage_vocabulary`）。
- `ops.json` 的 `linear_attention_ops[].validation` 现在是 `{stage: status}` 平铺；`ascriptor_pin.release_scope`
  标 supported=a5、deferred=a2/a3；`models.json` 有 `ascriptor_a5_abi`。
- 运行记录**不得含机器信息**（主机名/IP/账号/路径）：机器用 `machine_specs.md` 里的代号。

## 要求

1. schema：`validation` 改为按 SoC 分层（例如 `{a5: {stage: status}, a2: {...}}`）；现有内容**原样迁到 a5 下**；a2/a3 初始全 `untested`。
2. 运行记录 `docs/matrix/runs/<日期>-<短名>.json`：`commit`、`soc`、`machine_alias`、`cann`、`command`、`numbers`、`log_ref`（`tmp/` 下的相对路径，仅供追溯）。
3. `tools/record_run.py`：从一次运行的参数生成记录文件，拒绝含 IP / 绝对路径的字段。
4. `gen_matrix.py --check`：新增校验 ——
   - 每个 `passed` 格必须引用存在的运行记录，且记录的 `soc` 与格子的 SoC 一致；
   - 一次性豁免清单：迁移前已有的 A5 `passed` 格若找不到记录，放进显式的 `legacy_unrecorded` 列表（**列出来**，不是静默放行），并在生成的 README 里标注。
5. `.github/workflows/host-ci.yml`：主机侧 `pytest tests/ -q`、`gen_matrix.py --check`、`pm_board.py --check`。
6. 迁移用一次性脚本做（可放 `tools/` 后删，或留在 `tmp/` 并在 DONE 里给出），**不要手改大块 json**。

## 验收

- [ ] 迁移后 README 的 A5 内容与迁移前在语义上一致（给 diff 摘要）；新增 SoC 维度的展示。
- [ ] 合成反例：去掉某格的运行记录 → `--check` 失败；记录 soc 不符 → 失败；记录含 IP → `record_run.py` 拒绝。
- [ ] `legacy_unrecorded` 列表完整列出。
- [ ] CI workflow 能在本地等价跑通（给出命令与输出计数）。
- [ ] 主机侧 `pytest tests/ -q` 计数只增不减。
