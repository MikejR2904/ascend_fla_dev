## 这条任务是怎么来的

用户直接给的排期（D-PM-22）：GDN 前向（GDA-01，已完成）→ GDN 补 GQA/GVA 分组（GDA-02，已完成）→
**PGDN 前向（本任务）**→ backward → decode → 性能。`docs/research/pkda_semantics.md` 确立了权威来源：
论文 *Preconditioned DeltaNet*（[arXiv:2604.21100](https://arxiv.org/abs/2604.21100)），已合入上游 fla
（PR [#950](https://github.com/fla-org/flash-linear-attention/pull/950)）。**PGDN 是 GDN 加一层 ATK
预条件，不是新算子族**；ATK 那一步与 PK-02 共享结论（`pkda_semantics.md` §4）。**先读该文档全文**，
尤其 §3、§4、§7。没有已发布的预训练权重（§5），本任务到不了"真实 logits"这一级。

## 范围（窄）：只支持下面这些，其余在发射 kernel 之前显式报错（`AGENTS.md` §7）

与 `ascend_fla/ops/gdn_chunk_fwd.py` 现有门控逐项一致（PM 已对着代码核过），**不悄悄扩大**：

| 项 | 支持 | 其余 |
|---|---|---|
| 布局 | token-major 连续 `q,k:[B,T,H,128]`、`v:[B,T,HV,128]`（K=V=128） | `head_first`、非连续、varlen 报错 |
| T | 正的 64 的倍数，≤ 4096 | 其它 T 报错（`no-tail-path`） |
| 分组 | `HV % H == 0`，连续 `HV/H` 个 value head 共享一个 q/k head（同 GDA-02，照 fla naive 的语义） | 其它报错 |
| 门控 | `g,beta:[B,T,HV]` 标量；`g_atk,beta_atk:[B,T,H]`（**不随 HV 复制**）；`g ≤ 0`、`beta∈[0,1]`、`g_atk ≤ 0`、`beta_atk∈[0,1]`（ATK 状态保持正定；依据是 fla 层里 `beta_atk` 由 sigmoid 产生，为申领人自述，冻结 ABI 时对源码证实）；均有限 | 越界/非有限报错 |
| dtype | q/k/v 同为 FP32 或 BF16；门控类张量 FP32 | 混用报错 |
| `block_dim` | 1 或 2 | 其它报错 |
| 归一化 | 只支持 kernel 内对 q/k 做 L2 归一化**开启**这一种 | 关闭的组合报错 |
| 初始状态 | 主状态与 ATK 状态都只支持 None（零） | 传张量报错 |
| `scale` | 默认 `128**-0.5` | 其它值报错 |
| ATK 超参 | fla 默认值（`x=1.5`、`center=-0.2`，见 `pkda_semantics.md` §4；`eps` 以 pin 住的源码为准） | 其它值报错 |
| 输出 | `o`；可选返回两个**互相独立**的 FP32 状态：主状态 `[B,HV,128,128]`、ATK 状态 `[B,H,128]` | — |
| 其它 | 仅前向、仅推理 | backward / decode / varlen / 性能优化都**不在本任务**，不要顺带做 |

## 口径决定（PM 对申领人提问的回答）

1. **oracle**（`AGENTS.md` §1、§6）：
   - **A（语义权威，必须）**：fla `precond_gated_delta_rule` 的 `naive.py`（CPU FP32）。
   - **B（独立参考，必须）**：一份**不复用 A 代码**的独立 CPU 参考，运行时生成，按 `pkda_semantics.md` §4
     的算法自己写；chunk 与逐 token recurrent 互为 oracle（`AGENTS.md` §6 的硬判据）。
   - **torch_npu 组合 oracle**：`AGENTS.md` §6 的第二 oracle 要在 NPU 上同形状拼。沿用 GDA-01/02 的先例，
     真机数字对 A 与 B 两个 CPU oracle 判定，**不要求**再拼一份 torch_npu 组合实现；它可以作为同卡测量的基线之一。
   - **fla Triton chunk 实现**：**不要求，也不得声称验证过**（无 GPU，且与 naive 在近零行/BF16 物化上不等价，
     见下）。文档里引用它就标"未验证"。
2. **归一化语义分叉（必须写进文档并量化）**：申领人读 pin 住的源码后报告：naive 用 FP32 的
   `F.normalize`（`eps=1e-12`，即 `x/max(‖x‖,1e-12)`），而 chunk 路径的 `l2norm_fwd` 是
   `x/sqrt(Σx²+1e-6)` 且以输入 dtype 物化归一化后的 q/k。**PM 已于 2026-09-19 对 pin 住的源码核实**（`precond_gated_delta_rule/naive.py:110-111` 用 `F.normalize`；
   chunk 路径 `l2norm_fwd`，`use_qk_l2norm_in_kernel` 默认 True，读/写 key 分成 `k_read` / `k_write`）。 二者在近零行、BF16 物化下不等价（‖x‖=1e-4 时前者模长 1.0、
   后者约 0.0995）。本任务的 kernel 取 **naive 语义**（依据 `AGENTS.md` §1：naive.py 是语义权威）；
   `pgdn_chunk_fwd_gate_range.md` 要写明这处分叉、在近零行（‖x‖ 取 1e-2、1e-4、1e-6、0 各一档）
   量化两种语义的差，并在入口文档声明"与 fla Triton chunk 路径在近零行上不逐位一致，是有意选择"。
   与本仓 KDA 层已记的同型缺口 `kda-layer-l2norm-eps-formula-diverges`（`docs/matrix/gaps.json`）交叉引用。
3. **精度预算**（沿用 GDA-01/02）：**FP32** 下 `o`、`final_state`、`final_A_state` 三者相对 L2 ≤ 1e-4，
   对 A 与 B **各报一组**；**BF16** 只做输出质量检查，≤ 5e-3，报数，不作对错判定（`AGENTS.md` §6）。
4. **真机验收是必须项**（用户 2026-09-19 决定，D-PM-26）：DONE 之前必须在 A5 真机上完成原生测试，
   通过后可合入。内容见"真机验收（必须）"一节。

## 已知陷阱

- **别把 PGDN 和 PKDA 的门控混着看**：PGDN 是标量 `[B,T,HV]`，PKDA 是 channel-wise `[B,T,H,K]`，
  两者的量程分析不能共用一份结论（PK-02 的结论只覆盖 PKDA）。本任务不依赖 PK-02 的产出；
  若 PK-02 先合入，复用其 ATK 精度结论并交叉引用，否则自己复核。
- **ATK 状态与主状态是两个独立递推量**，维度数不同（`[B,H,128]` vs `[B,HV,128,128]`），
  chunk 边界处的进位各自处理，入口显式分开检查（`pkda_semantics.md` §7）。
- `g_atk,beta_atk` 是 per-`H`，`g,beta` 是 per-`HV`：分组复制只作用于 q/k 与 v 侧，
  **不要**把 ATK 的门控也复制到 `HV`。
- 新增 kernel 里凡是"4 维 GM 张量，B/H 标量索引、T/D 切片"的搬运，对照 `docs/matrix/gaps.json` 的
  `ascriptor-gm-transfer-two-slice-row-gap`（`gm_transfer` 双切片行间距漏算），显式传正确的行间距。
- `M` 恒有界只保证 `M` 本身不溢出，**不代表** `k_precond` 进入后续各阶段之后精度不受影响，要测。
- `run.py` 的位置参数是 `{reference,check,profile}`，`sim`/`pipesim` 是 `check` 的 `--launcher` 取值。
