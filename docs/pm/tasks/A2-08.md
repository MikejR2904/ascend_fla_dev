# A2-08 Kimi-Linear 注入脚手架（主机侧，CPU fp32）

- 波次 / SoC：W0 / any（纯 CPU；真机整模型在 A2-16）
- 优先级：P2 · 时限：16h · 依赖：A2-05
- 需要：fla、transformers；下载 HF 的 `config.json` 与 modeling 代码（**不下载权重**）
- 写集：`ascend_fla/models/**`、`tests/test_models_kimi.py`

## 目标

首波第一个整模型是 **Kimi-Linear-48B-A3B**。本任务在没有 NPU 的情况下把"注入"这件事做对：
直接用 HF（trust_remote_code）的模型定义，**只把 KDA 层替换成本仓的 `KimiDeltaAttention`**，不重写 modeling 文件
（`AGENTS.md` §9 窄切片 / 注入原则）。

## 背景（摘录）

- 模型源：`https://huggingface.co/moonshotai/Kimi-Linear-48B-A3B-Instruct`（`docs/matrix/models.json`：hidden 2304、
  H = HV = 32、K = V = 128、conv 4、27 层）。**层的排布（哪几层是 KDA、哪几层是全注意力）以 config 与 modeling 源码为准**。
- 本仓层：`ascend_fla/layers/kda.py` 的 `KimiDeltaAttention`，参数名与 fla 逐项对齐；两条路径
  `mode="chunk"`（T 必须是 64 的倍数）与 `mode="fused_recurrent"`（T ≤ 16，不可求导），cache 为两键字典（见 A2-05）。
- 本仓算子入口的硬约束（`AGENTS.md` §7：不满足即报错，绝不静默兜底）：
  - `no-tail-path`：chunk 路径 `T % 64 == 0`。
  - `c1-multihead-o-corrupt` 闸：`C == 1 and B*HV > block_dim` 报错（64 ≤ T < 128 的 prefill 直接撞上）。
  - `qk-l2norm-not-in-kernel`：q/k 的 l2norm、门控变换、beta sigmoid 由层做 —— **门控挡不住漏做**，注入时要逐项核对。
- CPU 上没有 NPU kernel：用 `ascend_fla/reference/kda.py` 的 torch 递推替身跑本仓层（参照 `tests/test_kda_layer_npu.py` 的 CPU 参考做法）。

## 要求

1. `ascend_fla/models/kimi_linear.py`：给定 HF 模型实例，替换其 KDA 层并搬运权重；替换前后参数名一一对应，缺一个或多一个都报错。
2. prefill 路由（显式、可测、有文档）：
   - `T = 64·n + r`：前 `64·n` 走 chunk，余下 `r` 个 token 走 decode 路径接续 cache；
   - `64 ≤ T < 128` 撞 C=1 闸时：选一个**精确**的办法（按头切分到 `B*HV ≤ block_dim`，或整段走 decode），写明理由；**不许**悄悄换近似路径。
3. 缩小配置：保持每个 KDA / 注意力层的**真实形状**，允许减少层数、专家数与 MLP 中间维以装进 CPU 内存，改了什么逐项记在测试里。

## 验收

- [ ] 同一份随机权重下，"HF 原 KDA 层"（fla 在 CPU 上可用的 naive 路径）与"注入后的本仓层（torch 参考替身）"：
      logits 在 fp32 下相对 L2 ≤ 1e-5，并**逐层**报 hidden state 差异。若 fla 的 KDA 层在 CPU 上跑不了，改在层级对 `fla.ops.kda.naive` 验证，并在 DONE 里说明。
- [ ] 路由测试覆盖 T ∈ {63, 64, 127, 128, 129}，prefill + 逐 token decode 5 步，**逐 token 报数**。
- [ ] 每条不支持的输入都有"报错"断言，没有静默路径。
- [ ] 主机侧 `pytest tests/ -q` 计数只增不减。

## 已知陷阱

- 不复制 `modeling_*.py`；注入式意味着上游规格更新时本仓零维护。
- 算子级精度指标不能外推到任务级（`AGENTS.md` §6），本任务只报数值一致性。
