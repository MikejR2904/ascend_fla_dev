# BF-01 GDN chunk 前向：BF16 原生 kernel（含 GQA/GVA 分组），A5 真机

- 波次 / SoC：W0 / a5 · 优先级：P0（用户 D-PM-35：后续 BF16 优先）· 时限：24h · 依赖：`GDA-02`（已完成）
- 需要：ascriptor、fla、a5 真机（D-PM-34）
- 写集：`kernels/projects/a5/gdn_chunk_fwd_bf16/**`、`ascend_fla/ops/gdn_chunk_fwd.py`（只加 BF16 分派，FP32 路径逐位不变）、`tests/test_gdn_chunk_fwd_bf16.py`、`docs/research/gdn_chunk_fwd_bf16.md`
- **先读 `docs/pm/bf16-kernel-side.md`**（什么算 kernel 侧、统一验收、陷阱）；本文只写这条任务特有的部分。

## 这条任务是怎么来的

用户 2026-09-19（D-PM-35）：BF16 计算必须在 kernel 里做，不能在 host 侧完成；后续 BF16 优先。GDN 前向（GDA-01/02）现在的 BF16 入口是 `q.float()` → FP32 kernel → 输出 `.to(q.dtype)`，即 host 侧加宽与转回（`ascend_fla/ops/gdn_chunk_fwd.py`）。本任务把 BF16 路径做成 kernel 侧。

## 范围

- 域与 GDA-02 的 FP32 前向逐项一致：token-major 连续 `q,k:[B,T,H,128]`、`v:[B,T,HV,128]`、`g,beta:[B,T,HV]`（FP32；`g≤0`、`beta∈[0,1]`、有限）、T 是 64 的倍数且 ≤ 4096、`HV%H==0`、`block_dim∈{1,2}`、`scale=128**-0.5`、只接 `initial_state=None`；
  BF16 的 `q/k/v` → BF16 的 `o`，`final_state` 仍 FP32。其余在发射 kernel 之前显式报错（`AGENTS.md` §7）。
- 起点（只读）：上游 pin 的 `a5.gdn_fwd`（BF16 operand，不带分组）与本仓 `kernels/projects/a5/gdn_chunk_fwd`（FP32，带分组）。分组用 kernel 内的 head 索引（q/k 头号 = value 头号 // (HV/H)）；
  若一定要复制 q/k，只能是无算术、无转换的布局操作，并在 DONE 里点名。
- 新建派生单元 `kernels/projects/a5/gdn_chunk_fwd_bf16/`。公共入口 `chunk_gdn` 只加分派：BF16 走新单元，FP32 走现有路径。
- 不含：反向（`BF-02`）、decode、性能优化。

## 验收

- [ ] 通则 §1：BF16 公共入口的 host 算子审计（真机，附算子列表）；入口源码里不再有 BF16 路径的 `.float()` / `.to(dtype)`。
- [ ] 通则 §2：BF16 校准先行（误差地板 F 与预算写进 `docs/research/gdn_chunk_fwd_bf16.md`，实现前定死）。
- [ ] 通则 §3 真机：完整 workload 先跑；`HV/H ∈ {1,2,4,8}` × `C ∈ {1,2,3,64}`（奇偶 C 都要）、多 batch；`bd` 间输出逐位相同；输入不被修改；NaN 预填。FP32 路径改前改后逐位相同。
- [ ] 通则 §5：同卡三轮三明治，BF16 新路径 vs 现有 FP32 路径，如实标注 baseline，不设速度门槛。
- [ ] 入口拒绝范围外的组合并说清哪条约束不满足；`git diff --stat` 对 `reserved_paths` 为空；没有改 FP32 单元源码。
- [ ] 预算：`o` 与 `final_state` 对 A（pin 版 naive，CPU FP32，喂 BF16 舍入后的输入）与 B（独立 CPU 参考）各相对 L2 ≤ 1e-2 且 ≤ 3F，逐项报数字。

## 已知陷阱

- GDA-02 的教训：分组求和 / 复制漏了会在 `HV>H` 时静默出错，而 `HV==H` 全对——网格必须含 `HV/H>1`。
- 上游 `a5.gdn_fwd` 的精度模型（BF16 立方操作数、2% 预算）不是本任务的预算；口径见通则。
- 一个算子名一个进程一份 build；所有 kernel 在首次执行前编完（`AGENTS.md` §5）。
