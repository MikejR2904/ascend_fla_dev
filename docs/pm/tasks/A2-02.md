# A2-02 让 SoC 在代码里显式化：`platform.py` + 去掉写死的 `device="a5"`

- 波次 / SoC：W0 / any（纯主机侧，不需要 NPU 与 ascriptor）
- 优先级：P1 · 时限：10h · 依赖：无
- 写集：`ascend_fla/platform.py`、`ascend_fla/runtime/compile.py`、`ascend_fla/ops/kda/**`、`ascend_fla/layers/kda.py`、
  `tests/test_platform.py`、`tests/conftest.py`

## 目标

SoC 顺序改为 A2 → A3 → A5 之后，代码里仍然到处默认 `device="a5"`、kernel 单元路径写死
`kernels/projects/a5/…`、`SUPPORTED_BLOCK_DIM` 与 `MAX_GATE_SPAN` 只有 A5 的实测值。**在 A2 上用 A5 的门控上限
就是静默错误。** 本任务把"哪个 SoC、这个 SoC 上实测过什么"变成显式的、按 SoC 查表的能力声明。

## 背景（摘录）

- `AGENTS.md` §9 早就规划了 `ascend_fla/platform.py`（"SoC/CANN 探测、能力门控，不满足即报错"），但还没建。
- 目前写死 A5 的地方（`grep -rn '"a5"\|projects/a5' ascend_fla`）：`runtime/compile.py` 的 `compile_kernel(device="a5")`、
  `ops/kda/__init__.py` 的 `prepare`、`ops/kda/autograd.py` 的 `chunk_kda`、`ops/kda/chunk.py` 的 `_kernels_root` /
  `_stable_kernels_root`、`ops/kda/chunk_bwd.py`、`ops/kda/fused_recurrent.py` 的 `_unit_root`。
- A5 的实测能力：`block_dim` 契约到 4（decode kernel 到 28）；物理 28 cube / 56 vec，profile 声明 32 / 64，
  超物理核数会死锁；门控上限 `MAX_GATE_SPAN = {stable: {forward: 155, backward: 105}, upstream: {80, 80}}`。
- 编译缓存签名（`runtime/compile.py` 的 `_signature`）含 device 字符串；**a5 的签名必须不变**，否则所有已有缓存失效、
  而且会让"改没改算式"变得难以判断。
- `runtime/binding.py` 的 `_claim_op_name()`：一个算子名一个进程一份 build。

## 要求

1. `platform.py` 提供：
   - SoC 解析：`ASCEND_FLA_SOC` 环境变量 → 设备探测（torch_npu 的设备名；识别 Ascend950* → a5、910B* → a2、
     910_93 / 910C → a3，**以真机读数为准的映射在 A2-10 / A3 补齐**）→ 解析不出来就**报错**并说明怎么设。
     不许悄悄默认成 a5。
   - 能力表 `CAPABILITIES[soc]`：`qualified: bool`、`supported_block_dim`、`max_gate_span[impl][direction]`、
     `unit_root`（`kernels/projects/<soc>/`）、证据指针（一句话 + 文件）。a5 照现有常量填；**a2 / a3 填
     `qualified=False` 与空限值**，调用即报"该 SoC 未验收：<缺什么>"。
   - 入口检查函数，错误信息写清哪条约束、实际值是多少（`AGENTS.md` §7）。
2. 所有 `device="a5"` 默认值改为 `None` → 走 `platform` 解析；kernel 单元路径由能力表给。
   现有常量（`SUPPORTED_BLOCK_DIM`、`MAX_GATE_SPAN`）改成从能力表读，**保留原名作为 a5 的别名**以免破坏测试与基准脚本。
3. `tests/conftest.py`：主机侧没有 NPU，现有测试需要时显式设 `ASCEND_FLA_SOC=a5`（session 级），不要靠默认值。
   不得打乱现有 session fixture（它必须在第一次执行前编完所有 kernel，见 `AGENTS.md` §5）。

## 验收

- [ ] 主机侧 `pytest tests/ -q` 结果与改前**完全相同**（报改前/改后两组计数）。
- [ ] 新测试证明：a5 的编译签名与改前逐字相同（对几个 kernel 取签名比较，改前的值写死在测试里）。
- [ ] soc=a2 / a3 调 `chunk_kda`、`prepare`、`fused_recurrent_kda` 都在**编译之前**报清楚的"未验收"错误
      （校验要排在有副作用的步骤之前 —— plan.md 第二期教训 4）。
- [ ] 没有 NPU、没设环境变量时报错信息里有设法。
- [ ] `python tools/gen_matrix.py --check` 通过。

- 不要顺手改门控数值或 block_dim 上限 —— 只搬家，不改值。
