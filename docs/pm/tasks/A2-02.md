# A2-02 让 SoC 在代码里显式化：`platform.py` + 去掉写死的 `device="a5"`

- 波次 / SoC：W0 / any。纯主机侧，不需要 NPU，也不需要 ascriptor
- 优先级：P1 · 时限：10h · 依赖：无
- 写集：`ascend_fla/platform.py`、`ascend_fla/runtime/compile.py`、`ascend_fla/ops/kda/**`、`ascend_fla/layers/kda.py`、
  `tests/test_platform.py`、`tests/conftest.py`

## 目标

SoC 顺序改成 A2 → A3 → A5 之后，代码没跟上：`device="a5"` 还是到处的默认值，kernel 单元路径写死在
`kernels/projects/a5/…`，`SUPPORTED_BLOCK_DIM` 与 `MAX_GATE_SPAN` 里装的也只有 A5 的实测值。
**在 A2 上用 A5 的门控上限就是静默错误。** 本任务要把"跑在哪个 SoC 上、这个 SoC 上实测过什么"
变成显式的、按 SoC 查表的能力声明。

## 背景（摘录）

`AGENTS.md` §9 早就规划过 `ascend_fla/platform.py`，写的是"SoC/CANN 探测、能力门控，不满足即报错"，但一直没建。

写死 A5 的地方用 `grep -rn '"a5"\|projects/a5' ascend_fla` 能扫出来：`runtime/compile.py` 的
`compile_kernel(device="a5")`、`ops/kda/__init__.py` 的 `prepare`、`ops/kda/autograd.py` 的 `chunk_kda`、
`ops/kda/chunk.py` 的 `_kernels_root` 与 `_stable_kernels_root`、`ops/kda/chunk_bwd.py`，
还有 `ops/kda/fused_recurrent.py` 的 `_unit_root`。

A5 上实测出来的能力是这些：`block_dim` 契约到 4，decode kernel 到 28；物理 28 cube / 56 vec，
而 profile 声明 32 / 64，超物理核数会死锁；门控上限
`MAX_GATE_SPAN = {stable: {forward: 155, backward: 105}, upstream: {80, 80}}`。

编译缓存签名（`runtime/compile.py` 的 `_signature`）里含 device 字符串。a5 的签名必须不变，
否则所有已有缓存失效，而且会让"改没改算式"变得难以判断。另外 `runtime/binding.py` 的
`_claim_op_name()` 管着一个算子名一个进程一份 build。

## 要求

1. `platform.py` 提供 SoC 解析、能力表和入口检查。解析先看 `ASCEND_FLA_SOC` 环境变量，再做设备探测
   （读 torch_npu 的设备名，Ascend950* → a5、910B* → a2、910_93 / 910C → a3；以真机读数为准的映射在
   A2-10 和 A3 补齐），两条路都解析不出来就报错并说明怎么设，不许悄悄默认成 a5。能力表 `CAPABILITIES[soc]`
   存 `qualified: bool`、`supported_block_dim`、`max_gate_span[impl][direction]`、`unit_root`
   （`kernels/projects/<soc>/`）和证据指针（一句话加文件）。a5 照现有常量填，a2 与 a3 填 `qualified=False`
   与空限值，调用即报"该 SoC 未验收：<缺什么>"。入口检查函数的错误信息要写清哪条约束没满足、实际值是多少
   （`AGENTS.md` §7）。
2. 所有 `device="a5"` 默认值改为 `None`，走 `platform` 解析；kernel 单元路径由能力表给。现有常量
   `SUPPORTED_BLOCK_DIM` 与 `MAX_GATE_SPAN` 改成从能力表读，但保留原名作 a5 的别名，免得破坏测试与基准脚本。
3. `tests/conftest.py`：主机侧没有 NPU，现有测试需要时显式设 `ASCEND_FLA_SOC=a5`（session 级），不要靠默认值。
   现有 session fixture 不得打乱，它必须在第一次执行前编完所有 kernel，见 `AGENTS.md` §5。

## 验收

- [ ] 主机侧 `pytest tests/ -q` 结果与改前完全相同（报改前、改后两组计数）。
- [ ] 新测试证明 a5 的编译签名与改前逐字相同：取几个 kernel 的签名比较，改前的值写死在测试里。
- [ ] soc=a2 或 a3 时调 `chunk_kda`、`prepare`、`fused_recurrent_kda`，都要在编译之前报出清楚的"未验收"错误
      （校验排在有副作用的步骤之前，见 plan.md 第二期教训 4）。
- [ ] 没有 NPU、又没设环境变量时，报错信息里有设法。
- [ ] `python tools/gen_matrix.py --check` 通过。

## 验证命令

```bash
python -m pytest tests/ -q
python -m pytest tests/test_platform.py -v
grep -rn '"a5"' ascend_fla | grep -v platform.py    # 期望只剩文档/注释
```

## 与仓主并行轨道的边界

仓主在 A5 上有一条并行的 GDN-2 轨道（见 `docs/handoff.md` §1），它和本任务共用两个文件：
`ascend_fla/runtime/compile.py` 与 `tests/conftest.py`。那条轨道的 `ops/gdn2`、`layers/gdn2.py`、
`kernels/projects/a5/gdn2_*` 等路径列在 `docs/pm/board.json` 的 `reserved_paths` 里，**一个字都不要动**。

因此本任务多一条硬要求：改完之后 GDN-2 那条链必须照常工作。`tests/test_gdn2_model.py` 与
`tests/test_gdn2_recurrent.py` 要跑，计数与改前一致（主机侧该 skip 的照旧 skip）。
验收里"a5 编译签名逐字相同"这条本来就是为这个服务的 —— GDN-2 的算子也走同一个 `compile_kernel`。

## 已知陷阱

"缓存键不能比缓存贵"是 `AGENTS.md` §6 的铁律三。SoC 解析一旦落在每次前向的热路径上，就必须是 O(1) 的，
进程内备忘一下。

不要顺手改门控数值或 block_dim 上限。只搬家，不改值。
