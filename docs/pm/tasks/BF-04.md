# BF-04 PKDA chunk 前向：BF16 原生 kernel（含 ATK），先做精度研究，A5 真机

- 波次 / SoC：W0 / a5 · 优先级：P0（用户 D-PM-35：后续 BF16 优先）· 时限：24h · 依赖：`PK-04`（已完成）
- 需要：ascriptor、fla、a5 真机（D-PM-34）
- 写集：`kernels/projects/a5/pkda_chunk_fwd_bf16/**`、`ascend_fla/ops/pkda_chunk_fwd.py`（把「BF16 显式拒绝」换成 BF16 分派，FP32 路径逐位不变）、`tests/test_pkda_chunk_fwd_bf16.py`、`docs/research/pkda_chunk_fwd_bf16.md`
- **先读 `docs/pm/bf16-kernel-side.md`**（什么算 kernel 侧、统一验收、陷阱）；本文只写这条任务特有的部分。

## 这条任务是怎么来的

用户 2026-09-19（D-PM-35）：BF16 计算必须在 kernel 里做，不能在 host 侧完成；后续 BF16 优先。PKDA 前向目前只有 FP32，公共入口显式拒绝 BF16。仓内记录的是范围决定（PK-02 把 BF16 定为非验收项）而不是不可行证明；用户要求 BF16 优先。技术上的疑点有实测背书的只在 FP32 一侧：门控前缀差的抵消（PK-02 跨度 4096 时 S=1.34e-4，PK-04 的「一大后小」门控上偏差 3.36e-4）已经逼近或超过 1e-4 预算，BF16 尾数更短，大概率更糟——所以先研究、再实现。

## 范围

- **第一步：精度研究（在写 kernel 之前，CPU 上）**。写一个「BF16 operand 舍入 + FP32 累加」的模拟器，逐阶段（prepare / scores / WY / scan / output）判定哪些 matmul 的 operand 可以是 BF16、哪些必须留 FP32 vector 计算
  （门控前缀、`exp(gc_i − gc_j)` 因子、ATK 对角状态、三角求逆的稳定性）。结论写进 `docs/research/pkda_chunk_fwd_bf16.md`，附各阶段误差；**实现方案与预算据此在写 kernel 前定死**。
  结论若是「某一阶段在 BF16 operand 下无法达到预算」，发 `RISK`（`soc-assumption` 或 `silent-wrong-result`）报给 PM，不要自己降预算。
- 域与 PK-04 的 FP32 前向一致：raw q/k 原样消费（不归一化，`‖k‖≤1+1e-5`）、`g/g_atk≤0`、`beta/beta_atk∈[0,1]`、`initial_A_state≥0`、`B∈{1,2}`、`T=1..4096`（含尾块）、`H=1..32`、`K=V=128`、`block_dim∈{1..4}`。
  BF16 的 `q/k/v` → BF16 的 `o`；`final_state`、`final_A_state` 仍 FP32；两个状态独立、可选输入。
- 结构参考（只读）：上游 pin 的 `a5.kda_fwd`（BF16 kernel：gate / intra / wy / `tril_inverse64_v2_strict_bf16` / recurrent）与本仓 PKDA FP32 五阶段（含 PK-04 的 Kahan 前缀求和，保留）。新建 `kernels/projects/a5/pkda_chunk_fwd_bf16/`。
- **门控域要在 BF16 路径上重测**（通则 §4）：上界 = 预算仍成立的最深实测点，下界 = 调用方真实会送进来的值，必含「每 chunk 首项 ≈ −155、其余 ≈ −1e-5」这类一大后小模式；
  BF16 可用域若比 FP32 的 155 窄，属域变化：先发 `RISK`，PM 按 D-PM-33 问用户，**不得自行收窄后合入**。

## 验收

- [ ] 通则 §1：BF16 公共入口的 host 算子审计（真机，附算子列表）；入口源码里不再有 BF16 路径的 `.float()` / `.to(dtype)`。
- [ ] 通则 §2：BF16 校准先行（误差地板 F 与预算写进 `docs/research/pkda_chunk_fwd_bf16.md`，实现前定死）。
- [ ] 通则 §3 真机：完整 workload 先跑；16 个契约 case + 尾块 + 独立双状态与续接 + 域内对抗性门控 + `bd ∈ {1,2,3,4}`；`bd` 间输出逐位相同；输入不被修改；NaN 预填。FP32 路径改前改后逐位相同。
- [ ] 通则 §5：同卡三轮三明治，BF16 新路径 vs 现有 FP32 路径，如实标注 baseline，不设速度门槛。
- [ ] 入口拒绝范围外的组合并说清哪条约束不满足；`git diff --stat` 对 `reserved_paths` 为空；没有改 FP32 单元源码。
- [ ] 预算：`o`、`final_state` 对 A（pin 版 PKDA naive，喂 BF16 舍入后的输入）与 B（独立 CPU 参考）各相对 L2 ≤ 1e-2 且 ≤ 3F；`final_A_state` ≤ 1e-4。
- [ ] 精度研究结论、逐阶段误差与最终方案写在文档里；BF16 的门控域双边有实测依据。

## 已知陷阱

- PK-02 里「A 相对 L2 = 0」只对 CPU 模型成立；真机的 `exp/ln` 不保证逐位相同。
- 不要把 KDA 的 BF16 证据当 PKDA 的证据（PK-02 已写明）。
- 「BF16 值的 FP32 张量」不算 BF16 kernel。
