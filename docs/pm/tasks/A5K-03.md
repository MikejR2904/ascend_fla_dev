## 目标：回答四个问题

1. **是 kernel 内的竞态 / 同步缺陷，还是环境 / 卡 / CANN beta 的问题？**（两种都可能；机制未定位前谁也不能排除。）
2. 如果是 kernel：**精确到源码行与事件**——哪一对读 / 写无序、哪个 `DEvent` / `Mutex` 的信用与槽数不匹配、缺哪一次同步。
3. **预测 → 干预验证**：由机制推出一个可证伪的预测，再用干预实验证实（见方法）。
4. **影响面**：哪些形状 / `bd` / `C` / `HV` 暴露；**为什么只有 dh0 不稳而 dAqk / dh / dv 稳定**；生产里 dh0（初始 state 的梯度）会不会被用到、错的形态是什么（整块旧值 / 部分写 / 哪些行）。

## 方法（硬要求，`AGENTS.md` §6.5）

- **不许按症状规律倒推**（A2-04 的教训：「C=1 坏、C=2 好」倒推出了错的根因）。要**机制 + 可证伪的预测 + 干预实验**，三样齐了才叫定位；只有相关性的结论要写成「假设」。
- **静态**：对上游 `scan_fused` 在失败形状（B2 / HV4 / C3、`bd4` 起，再扫 `bd` 与形状）跑 pipesim / 事件平衡分析，找最终 state 区域的**无序对**（A2-04 就是这样找到 Aqk 的）；列出 358–362 一带所有读 / 写 / 同步点与它们的信用 / 槽。
- **动态**：在复现卡（dev-A）上固定输入直接重放 **N ≥ 50 次**统计 dh0 哈希分布（12 次的小样本不够；零失败时给上界，如 Clopper–Pearson）；`bd` 与形状扫；与稳定卡对比；有 CANN 9.2.0 环境就做同一组重放的跨环境对照。**同步 / 捕获边界会改变复现概率**：加 host 同步或 profiler 后不稳定消失**不等于**修好，这类现象只能当线索。
- **干预**：在**实验性派生副本**里（新单元 `kda_scan_diag`，不接公开调度、不进 `ascend_fla/ops/**`）一次只动一个变量：加候选同步 / 去掉候选 hazard，预测 dh0 在复现卡上 N ≥ 50 次同哈希；**负对照**（无关改动，如只改注释 / 无关顺序）仍应不稳定；每个实验记录源码哈希与环境行。
- 若结论是**环境 / 卡问题**：给出区分证据（同代码同输入在别的卡稳定、卡的健康 / 日志、跨 CANN 对照），**不宣称修复**，并说明对我们的 A5 路径意味着什么（哪些环境需要标注）。
- 若结论是 **kernel 竞态**：给出精确机制 + **建议修法的描述**（供后续 kernel 批次，需要用户批准），**不合入生产、不接公开调度**。
