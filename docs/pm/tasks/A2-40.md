# A2-40 整网融合算子：清单、ABI 与验收设计（主机侧）

- 波次 / SoC：W0 / any。纯主机侧调研 + 设计，不需要真机
- 优先级：P1 · 时限：12h · 依赖：无
- 需要：ascriptor workspace（查可复用的算法单元）、fla（对照它把什么放进了 kernel）
- 写集：`docs/research/a2_fusion_ops.md`

## 为什么要有这条

算子本身跑得快，不等于整网跑得快。实测（`docs/handoff.md`）：KDA 整层 decode 一步 458µs，
**KDA 算子只占 18%，层里其余那十几个小算子占 67%** —— 七个投影、三个短卷积、两次 fp32 l2norm 往返、
一个 output norm，每个几乎没有计算量却各要一次 launch。把 kernel 再快一倍，整层只快 9%。

而且这些"周边"现在全是 torch 原生算子，带来两个后果：缺内置算子包的机器上层级验证根本做不了；
报层级性能时得把它们拆出来说，否则等于把 torch 的开销记在本仓算子账上。

本任务不写 kernel，只把**要做哪些、ABI 长什么样、怎么验收**定下来，供后续 A2-41 / A2-42 / A2-43 执行。

## 四个对象（看板 fusion 族）

| id | 现状 | 对应缺口 |
|---|---|---|
| `causal_conv1d` | `modules/convolution.py`，torch 实现，支持 cache 单步解码与 `T < kernel_size` 补零 | `modules-are-torch-not-kernels` |
| `fused_rms_norm_gated` | `modules/fused_norm_gated.py`，KDA 的 o_norm，sigmoid 门控 | 同上 |
| `qk_l2norm_gate` | 现在由层做：q/k 的 L2 归一化、门控变换、beta sigmoid | `qk-l2norm-not-in-kernel`（**P1，本仓唯一"错了不报错"的语义缺口**） |
| `packed_projection` | 七个投影分开算；合投影与图捕获都还没做 | `decode-layer-overhead` |

## 步骤

1. 逐个对照 fla：它把哪几步放进了 kernel（`use_qk_l2norm_in_kernel` 等开关），我们现在放在哪、为什么。
   给出语义差异表，标明哪些是"数值上合法但结果静默错"的面。
2. 查 ascriptor 侧可复用的算法单元：`matrix_normalization` 的 `row_l2`、`gated_approximations` 等，
   逐个写清能用哪一部分、缺哪一部分。`docs/matrix/ops.json` 的 `reusable_primitives` 是起点。
3. 为每个对象写 ABI 草案：输入输出张量、dtype、布局、标量、`block_dim` 约束、以及不满足时报什么错
   （`AGENTS.md` §7：不满足即报错，绝不静默兜底）。
4. 写验收判据：对哪个 oracle、什么形状、什么阈值。fp32 判定，报相对 L2 / max_abs_diff。
   `qk_l2norm_gate` 要特别说明怎么证明"融进 kernel 之后与层外做的逐位或按预算一致"。
5. 估工作量与拆分建议：哪些能进 A2-41（独立单元）、哪些必须进 kernel 批次（A2-42 改前向 kernel）、
   哪些是纯层侧改动（A2-43）。
6. 量程逐处判定（`AGENTS.md` §6）：这四个对象里所有 `exp` / 除法 / 规约类算式列表判量程，
   不要只看报错的那一处。

## 验收

- [ ] 四个对象每个都有：现状、与 fla 的语义差异、ABI 草案、验收判据、工作量估计。
- [ ] 可复用的 ascriptor 单元逐个点名，缺的部分写清楚。
- [ ] 量程表覆盖四个对象的全部相关算式，逐处给结论（含"恒 ≤1、下溢到 0 是正确结果"这类判断）。
- [ ] 拆分建议能直接落到看板（A2-41 / A2-42 / A2-43 的范围与依赖）。
- [ ] 没有写或改任何 kernel、模块代码。

## 已知陷阱

- `decode-layer-overhead` 那条缺口里写着处置顺序：图捕获 → 合投影 → 去 l2norm 的 dtype 往返。
  设计时要说明为什么按这个顺序，或者给出更好的理由推翻它。
- **profile 之前不要相信任何性能推断**（`AGENTS.md` §6 铁律一）。本任务不跑真机，所以所有性能话术
  都要标成"待测"，不能写成结论。
- `ShortConvolution` 本来就支持 cache 单步解码，别把已有能力当成缺口重做一遍。
