## 这条任务是怎么来的

A2-44（PR #99）让公开 `chunk_kda` / `fused_recurrent_kda` 支持 fla 式 raw flags，但 q/k 的 l2norm、`g = −exp(A_log)·softplus(g+dt_bias)`、beta 的 sigmoid 仍在 host 侧用 PyTorch 算子（FP32）完成（`chunk._prepare_inputs`，chunk 与 decode 共用），再舍入 / 传给 kernel。
`ascend_fla/layers/kda.py` 也走这条路（`use_qk_l2norm_in_kernel=True, use_gate_in_kernel=True`）。D-PM-35 / D-PM-37：BF16 计算与 dtype 转换必须在自编译 kernel 里；这三步是 D-PM-40 / D-PM-42 登记的「raw flags 存量例外」，本任务把它们搬进 kernel 并消除该例外。

## 范围：`_prepare_inputs` 的三步（当前语义，逐条以源码为准）

| 步骤 | 触发 | 输入（当前接受） | 计算（FP32） | 输出 |
|---|---|---|---|---|
| gate | `use_gate_in_kernel` | `g[B,T,HV,128]`、`A_log[HV]`、`dt_bias[HV*128]`，任意 floating | `g_out = −exp(A_log)[h] · softplus(g + dt_bias[h*128+k])`（`torch` 默认 softplus，beta=1、threshold=20） | FP32 `g_out[B,T,HV,128]` |
| q/k l2norm | `use_qk_l2norm_in_kernel` | `q,k[B,T,H,128]`，任意 floating | `x / sqrt(Σ_k x² + 1e-6)`（加性 epsilon，FLA v0.5.2） | 舍入到 `qk_dtype`：chunk 为 BF16，decode 为 `v.dtype`（BF16 或 FP32） |
| beta | `use_beta_sigmoid_in_kernel` | `beta[B,T,HV]`，任意 floating | `sigmoid(beta)` | FP32 `beta_out` |

- 某个 flag 关闭时对应输入**原样透传**（不进 kernel、不拷贝）——`_prepare_inputs` 现有的「never changes a disabled route」要保持，FP32 / 不带 flag 的路径改前改后逐位相同。
- **dtype 域（PM 裁定，D-PM-40 同型）**：raw `q/k/g/beta`（及 `A_log` / `dt_bias`）只接 **BF16 或 FP32**，kernel 内加宽 / 计算；FP16 / FP64 / 其它显式报错并说清哪条约束不满足（这是从「任意 floating（靠 host 加宽）」收窄——合入前 PM 单列给用户，你不要自行放宽或收得更窄）。输出 dtype 见上表；decode 的 `qk_dtype=v.dtype` 边界保持。
- **不做**：不改 `check_domain` 启发式与门控跨度检查的语义（它们是只读校验，D-PM-42 单列，BF-07 后仍是登记的只读例外）；不碰 `_scan_states` / `dw` 取负 / `log2(eg)`（FMT-02 登记的另一批存量例外，不属本任务）。

## 2026-09-20 澄清（依申领人的 RISK `contradicts-handoff`：FP32 输出的「1 ulp」判据；PM 承认是规格写宽了）

实现前校准（CPU、Torch 2.10.0+cpu、种子 7007、含 Kimi B1/T4096/H32/K128，92 条，自述）显示：**旧 host 实现自己对 FP64 参考舍入到 FP32 就有 2–3 ulp**（norm BF16→FP32：相对 FP64 最大 relL2 6.30e-08、逐元素相对误差 1.81e-07、对正确舍入 FP32 的最大 ULP=3；FP32→FP32：5.30e-08 / 1.76e-07 / ULP=2），两条路的 BF16 输出最多差 1 ulp。所以规格里「逐元素不超过 1 ulp」对 **FP32 输出**不成立。PM 裁定（采纳申领人的提案，并把比较对象写明）：

1. **BF16 输出**：对 FP64 正确舍入与对旧 host 各自最多 1 ulp、相对 L2 ≤ min(1e-2, 3F)（不变）。
2. **FP32 输出**：**不设 ulp 通过线**；相对 L2 与逐元素相对误差的预算 = **旧 host 对 FP64 的实测地板的 3 倍**（norm 另受 1e-2 上限），常规各 dtype 组合分别冻结。这等价于「新 kernel 对 FP64 不得比旧 host 对 FP64 差过 3 倍」，不是「对旧 host 近似」。ULP 分布对两个比较对象（对 FP64 正确舍入、对旧 host）**都报**，超过 1 ulp 的元素按规约 / sqrt / 除法的舍入边界**逐类列明并解释**，由 PM 评审核实；不把 2–3 ulp 擅自写成自动通过的阈值。
3. **端点**（`x²` 上溢使 norm 归零、`exp(A_log)` 上溢使 gate 为 −inf、subnormal / 下溢）：与旧 host 的 FP32 语义**逐点对照**——同一公式顺序下 kernel 应给出相同的 IEEE FP32 行为；若向量指令的 denormal / NaN / Inf 处理与 torch 不同导致差异，逐类写明差异与影响。**不新增数值闸、不收窄域**（要收窄先问用户）；常规地板与端点分开（你已经这么做了），不得拿端点的相对误差 1 去放宽常规预算。
4. 预算与 92 条校准记录随**第一个提交**冻结，事后不得放宽。

## 2026-09-20 端点比较口径追加（依申领人的 RISK `comparison-contract-boundary` 与 decode 定位；D-PM-48 / D-PM-50 / D-PM-51）

以下**只覆盖「端点」**，不改任何常规域判据、预算数值、155 / 105 门控或域：

1. **扩展非有限交叉端点**（D-PM-48 (1)）：CPU FP32 为语义权威，旧 NPU 是前任行为观测；每个点位报 candidate / 旧 NPU / CPU FP32 / FP64 四列，分三类写明机制与影响（candidate = CPU；candidate = 旧 NPU ≠ CPU；旧 NPU ≠ candidate = CPU）；不设「NaN / Inf 掩码相等」的通过线，不改 candidate；写可达性与公开入口对非有限 gate 的实际行为。
2. **golden 对 BF16 正确舍入后整个 (head, chunk) 切片为零**（D-PM-48 (2)）：按「对 golden 正确舍入 ≤ 1 ulp」判（数值 ULP；+0 / −0 是 0 步，符号差按观测如实报，不称逐位相同）；相对 L2 照报、原失败保留、不删逐头 / 逐 chunk 判据、列出这类切片；仅限此类。
3. **golden 整片是 FP32 subnormal、candidate 与实际旧 NPU 逐字节同为 ±0**（D-PM-50）：归入 native 下溢单列资格，不新增闸、不收窄域，保持失败、不放宽阈值；该片逐元素分类——(a) golden 为 FP32 正规数 → 普通判据；(b) golden 为 FP32 subnormal 且 candidate 为 ±0 → flush 类（报个数）；(c) 其它一律失败。与旧 NPU 逐字节相同只表示无回退、不是 CPU 正确性通过，DONE 不得写成通过；写可达性；其它 flag / bd / decode 上的同类切片按同一分类统计。
4. **decode 近零端点组的比较对象**（**用户 2026-09-20 同意，D-PM-51**）：范围只限 boundary-grid 里的近零 decode 端点组（`nearzero_*`，q / k 的 Σx² 远小于 eps、归一化被 eps 主导），其它任何 case 不适用；DONE 里列出用这条口径的 case 个数与 ID。这一组的 `final_state` 与 `o` 的判据 =
   - (A) 对**以 candidate 实际 native-prep 输出为输入**的 CPU FP32 reference：`final_state` ≤ 1e-5（BF-06 沿用值，不放宽）、`o` ≤ min(0.01, 3F)（原判据）；
   - (B) prep 单步已过冻结预算（q / k ≤ 1 ulp 且相对 L2 ≤ min(1e-2, 3F)；gate / beta 各自的冻结预算）；
   - (C) raw 与 prepared-public 的 `o` / `state` 逐位相同（真实字节 SHA，不用 `torch.equal`）；
   - 对**旧 prep 的 CPU reference** 的偏差（如 4.31e-4）作观测如实报，并写明分解（prep 的 BF16 舍入位置 vs 下游递推）。
   - **前提（补齐前不得对别的 case 用这条口径）**：① 普通 decode 的 state 1e-5 判据的比较对象是旧 prep 的 CPU reference 还是实际 prep 输出的 reference；② 若是前者，给普通域 state 对旧 prep reference 的相对 L2 分布（最大值与位置），并说明近零档 q / k 约 1% 元素差 1 ulp（173 / 185 / 16384）为何高于普通域，是哪一步公式与旧 host 不同；③ 近零 decode 里其它 flag / bd 切片有没有落在 1e-5 之上，个数与位置。
   - 普通域 decode 与 chunk 的判据一个字不变。

5. **剩余输出失败的端点类**（**用户 2026-09-20 批准 PM 建议，D-PM-52**）：boundary-grid 里 chunk（每 bd 16 例）与 decode（每 bd 44 例）的 nearzero 输出失败，按下面的定义归入「**只披露、不设通过线**」的端点类——这是披露，**不是通过**：
   - **类定义**：该 (head, chunk) 切片同时满足 (a) `|golden|max ≤ 32 × FP32 最小正规数`（≈ 3.76e-37；golden = 保存的 CPU FP32 golden，两套 oracle 各自判）；(b) candidate 与旧 NPU 逐位相同，或差不超过 1 个 BF16 ULP（chunk）/ 4 个 FP32 ULP（decode）。
   - **披露**：逐切片表（`remaining-output-failure-table.json`）照发布，原相对 L2 / ULP / 分类计数（normal 子集 L2、subnormal→0、subnormal→非零、CPU 零→非零）保留；DONE 与研究文档写明「无回退 ≠ CPU 正确性通过」，并附必要下界证明（decode 148/148、chunk 16/40 的逻辑无解）与范围核对（188/188 落在类内）。
   - **落在类外的任何失败一律仍是失败**，不因这一条被吸收；普通域判据、1e-5 / 0.05 / min(0.01, 3F)、155 / 105 门控、域、D-PM-48 / D-PM-50 / D-PM-51 都不变；**不改 inherited kernel、不批准 kernel 批次**（B 选项未选）。

## 预算与判据（实现前冻结，事后不得放宽）

**PM 不预设数字，你先校准**：把校准（对 FP64 参考的误差地板 F、逐量的分布）与由它导出的预算作为**第一个提交**（BF-02 的 `1a3cf5a` 那种做法），再写 kernel。PM 评审时核对：预算不比校准地板的 3 倍更松、没有空洞比较（零预算除外）、每个预算实现前后没变。下面是必须定的量：

- **前处理输出**对 FP64 参考与对 host `_prepare_inputs`（用一份逐字节钉住的前任副本，方式同 FMT-02 的 `baseline/`）：`g_out` / `beta_out`（FP32，逐元素相对误差与相对 L2）、q/k（BF16 或 FP32 输出，RNE 舍入位置差异：逐元素不超过 1 ulp、相对 L2 ≤ min(1e-2, 3F)、超 1 ulp 的元素数为 0 或有解释）。**不要求与 host 逐位相同**（`exp` / `log1p` / `sigmoid` / `sqrt` 的实现不同，舍入位置不同），但要**量化写明差**。
- **端到端**：`chunk_kda` 的 `o` / `final_state` 与六个梯度（对两个 CPU FP32 参考，预算沿用现有：`o` / state 0.05，dq / dv / dbeta / dh0 0.05、dk 0.15、dg 0.25，不放宽）；对 host-prep 路径同一输入的差报出来。
- **`bd` 间逐位相同**（含前处理 kernel 自己的行内求和；BF-08 的跨核归约另算），FP32 / 无 flag 路径改前改后逐位相同，输入不被修改，输出 NaN 预填后完整写满。
- **门控闸不变**（前向 155 / 反向 105）：融合后在跨度 {0, 100.8（fla 默认初始化的上界）, 105, 155} 上量化前后差，闸值不改（要改先问用户）；「有限」与「准」分别报。
- **按「量程」列表逐处判**（`AGENTS.md` §6）：`exp(A_log)` 上溢、softplus 的 threshold=20 两侧与大负值下溢、sigmoid 饱和、`x²` 上溢 / 下溢（`|x|` 很大 / 很小）、`eps=1e-6` 与零 / 近零行——每一处写成表，说明是「下溢到 0 就是对的」还是要闸，闸要双边实测；行为与 host 路径对不上的（NaN / Inf 传播等）要写明。
