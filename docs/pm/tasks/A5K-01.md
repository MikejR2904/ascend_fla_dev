## 缺陷回顾（A2-04 的结论，见 `AGENTS.md` §6 与 `gaps.json` 的 `c1-multihead-o-corrupt`）

`kda_sub45_fused_kernel` 的 `Aqk` L1 交接：两信用的 `aqk_l1_valid`
（`DEvent(Pipe.MTE1, Pipe.MTE2, preset=True)`）配上按 chunk 号取的固定槽
`aqk_slot = Var(c_idx % 2)`。一个头最后一个 chunk 的槽是 `(C-1)%2`，下一个头第一个
chunk 的槽是 `0`——**当且仅当 C 为奇数时相撞**，写方领先一周期踩进还没被读走的槽。
偶数 C 安全是因为槽恰好交替，不是因为多跑了一遍同步。

A2-04（PR #60）在 pipesim 上验证过修法：**槽按每核周期序号轮转**
`Var(((pair_idx - pair_begin) * C + c_idx) % 2)`，两信用配两槽，在 12 个奇数 C 格上
冒险归零、全头逐位正确；负对照（只轮转 q/qg）缺陷原样保留。**这是 pipesim 模型值，
没有真机验证过**——本任务要做的正是把这个已经在模型里验证过的修法，落到本仓
`kda_fwd_stable` 派生单元里，并在 A5 真机上验证。

## 步骤

1. **在本仓 `kernels/projects/a5/kda_fwd_stable/` 派生单元里应用 A2-04 验证过的修法**
   （槽按周期序号轮转），不改 ascriptor 仓（`AGENTS.md` §3）。**保留 A2-04 的负对照与
   未修复基线**作为回归测试，不要删掉"缺陷仍在"这个证据。
2. **双 oracle + 独立递推**：对 fla 的 KDA naive（CPU fp32）与一个独立写的递推参考，
   报每头/每 chunk 的 `o`/`final_state` 相对 L2 与 max_abs_diff。**沿用现有 stable 契约的
   比较预算（rtol=atol=0.02，max_relative_l2=0.05），不为了让缺陷"看起来修好了"放松它**。
3. **真机优先**：完整选定的 workload 先在 A5 上跑，覆盖 `C∈{1,2,3,4,5,6}`、重复头 vs 单头
   ownership、分组头（GQA）、零/非零 initial_state、现有合法 `block_dim`，以及 Kimi 真实
   形状 `H=HV=32, K=V=128`——这张网格直接对应 A2-04 诊断出的"奇数 C 结构性暴露"结论，
   不是随便选的。
4. **同步机制验证**：保留 A2-04 的负对照与未修复基线；用缩小形状的 pipesim 诊断证明
   修复后的槽生命周期/信用配对正确；**偶数 C 的输出要求与未修改基线完全一致
   （不只是"在预算内"），`block_dim` 不同时算式不变的部分要求逐位相同**（这是不需要
   参考的硬判据，AGENTS.md §6）。
5. **profile 之前不要相信任何性能推断**（AGENTS.md §6 铁律一）：先测基线，再谈优化。
   同卡三明治（baseline-candidate-baseline，warmup/repeat，三轮），T=1024/4096，
   对照独立的 torch_npu 组合基线，不能从 CPU golden 运行推断性能。只对"通过正确性"的
   case 报加速比。
6. **不跨机器/跨 SoC 继承结论**（AGENTS.md §6）：这台机器上测的门控跨度、`block_dim`
   上限、算子包覆盖，不能代表另一台 A5 机器，也不能代表 A2/A3。

## 已知陷阱

- 这不是"KDA-on-A5 提前"——只修这一个诊断清楚的缺陷 + 验证它，`A5-01`..`A5-06` 依然等
  A3 波次。别顺手把它们也解了。
- `run.py` 的位置参数是 `{reference,check,profile}`，`sim`/`pipesim`/`board` 是 `check`
  的 `--launcher` 取值，不是位置参数。
- A2-04 的结论是 pipesim 模型值，不是真机数——本任务是第一次真机验证，不要假设模型
  结论会原样在真机上重现，出入了要如实报。
- 偶数 C 的回归判据是"逐位相同"，不是"在预算内"——这是本任务专属的更严标准，
  因为它检验的是"没改坏原来对的部分"，不是"新代码是否正确"。
